# SysFileTree final-suite diagnosis

## Established failure

The retained failure is a directory-entry count mismatch, not a timestamp, size, permissions, or pathname formatting mismatch. `TEST_TREE_DIRECTORY` calls the assertion from `ootest/ooRexx/base/rexxutil/SysFileTree.testGroup:461`, and the assertion at line 547 compares expected `names~items` **1430** with actual `f.0` **1431** for `SysFileTree(/tmp/*, )`. The failure timestamp is local `2026-10-31 01:22:12.337942`; the crate exits 1 after 26 tests, 25 passing, while the oracle exits 0 with all 26 passing. The actual diagnostic contains 1431 rows with 1431 distinct paths, so the count agrees with the returned rows and is not explained by a duplicate result.

The exact failed raw output is `/tmp/codex-p9d-t88-final-gates-resume/suite-diagnostics/suite-2087764-374-crate-base__rexxutil__SysFileTree/crate-1/stdout`, SHA256 `3cd0bd075ee9038aa83f77e5e33eba01d8a0cd50b0f8b8dc285340cf48acc4f6`. Its `context.txt` hash is `cea8edf5406d1d19183b438567b3bfce2329e2387623edd6d89b8b3bad36deae`, and stderr is empty. The passing oracle bundle is `suite-2087764-364-oracle-base__rexxutil__SysFileTree/oracle-1` under the same diagnostics root; its stdout hash is `da30d7f3e2f2a451cd2524c52356e83b9dfc8767c8d9fd6ae8d3d8108470d806`. `evidence-manifest.json` records exact paths, sizes, and hashes for these bundles, the Stream bundles, gate command, per-test rows, delta, and static-input comparison.

## Causal dataflow

The line-461 call evaluates `.File~temporaryPath~listFiles` before entering the helper. `interpreter/RexxClasses/StreamClasses.orx:878` builds File objects from `list`, and Rust `dispatch/files.rs:169` implements that first scan with `std::fs::read_dir`; the helper then copies and sorts the expected objects at test-group lines 524–531. Only afterward does line 540 call SysFileTree, whose `builtin/rexxutil/tree.rs:171` implementation performs another independent scan through `search` and `entries`, formats accepted entries, and assigns `f.0` from the resulting vector length. Default options include files and directories without recursion, and the failed count assertion precedes the later per-entry metadata checks.

These two enumerations have no shared snapshot or synchronization. The suite uses eight group workers (`tests/suite.rs:76,1016,1042`), and both SysFileTree and Stream are in the pooled set rather than the four serial socket groups. Within each group the oracle runs before the crate (`suite.rs:771`), so oracle success does not compare the same directory state at the same instant. The preserved equality of 1057 static test inputs says nothing about concurrent files created in host `/tmp`.

## Ranked hypotheses and remaining uncertainty

1. **Shared temporary-directory mutation between scans, with Stream's `test_bug_1917` as the leading actor.** The actual listing starts with `/tmp/test_bug_1917`, size 34, modification time in the failure minute. `Stream.testGroup:2344–2345` creates that exact basename through `.TemporaryTestFile~new(, name)` and writes three lines totaling 34 Unix bytes; `OOREXXUNIT.CLS:2116–2119` places a missing-host temporary file in `.File~temporaryPath`. The crate Stream group's first started marker is `TEST_BUG_1917`, and the marker file was created at epoch `1793406132.305548723`, during the failing SysFileTree group's lifetime and about 32.4 ms before its assertion timestamp. This is strong actor-specific evidence, but the expected 1430 names and precise per-file creation syscall time were not recorded, so it does not prove that this particular path was absent from the first scan.

2. **Another process added an entry during the same interval.** The assertion enumerates the shared host temporary directory, which includes other suite and tool artifacts, and there is no filesystem event log. This produces the same count mismatch and remains possible even though the Stream candidate has a matching name, size, and overlapping lifetime. Multiple additions/removals with net difference one are also possible. The actual list alone cannot identify the set difference.

3. **An enumeration discrepancy on a stable directory.** This is less supported: both Rust paths use `read_dir`, the default wildcard accepts names including dot names, and the actual vector has no duplicates. SysFileTree additionally stats entries and may omit vanished/unstatable names, which normally reduces its count rather than explaining the observed extra entry on a stable directory. No retained stable-directory counterexample demonstrates a runtime fault. A controlled witness should distinguish the mutation mechanism from such a discrepancy before any production change.

Earlier bounded original and instrumented runs passed on both interpreters, as recorded in `task-8.8c-report.md` and the queue item. They did not establish a metadata cause and do not negate the current count failure. The new evidence narrows the failure to a shared-directory observation boundary and supplies a specific concurrent writer candidate. It does not justify a Flaky licence or an assertion relaxation.

## Smallest controlled experiment, proposed only

After the freeze and independent gates conclude, use the existing immutable interpreter and oracle in separate fresh, exclusively owned scratch directories with an explicit nonempty TMPDIR. Keep the Rexx script and captured output outside the enumerated directory, seed one fixed ordinary file, capture the full `.File~temporaryPath~listFiles` snapshot, then create and close exactly one named file before calling `SysFileTree` on the same directory. Record both complete name sets, counts, return codes, and the injected path; this should produce expected count 1 versus actual count 2 and exactly the injected set difference. A negative control with no inter-scan creation should produce equal singleton sets and counts, without sleeping, concurrency, or retries.

The oracle expectation follows directly from `FileNative.cpp:261`, which performs one `SysFileIterator` enumeration for File~list, and `RexxUtilCommon.cpp:662` plus `SysRexxUtil.cpp:477`, which independently enumerate and accept files/directories for SysFileTree. Neither implementation shares the earlier list or freezes directory contents, so a file synchronously created between calls belongs only to the second result on both interpreters. This witness establishes the race mechanism and expected behavior without asserting that it identifies the historical extra path. No witness has been executed during this diagnosis.

## Narrow allowable repair direction

If that controlled comparison confirms the mechanism, the narrow test-harness direction is to give this group's oracle and crate children their own fresh, populated temporary directories through TMPDIR while leaving protected ooTest sources and all assertions unchanged. Both implementations explicitly support TMPDIR: Rust `dispatch/files.rs:536` and oracle `SysFileSystem.cpp:1773`, reached through `FileNative.cpp:312`; the child launch points already reside in the owned Rust harness (`tests/suite.rs:581` and `crate_run_once`). Seed stable entries before launch and keep runner logs and diagnostic outputs outside the enumerated directory, so the final assertion retains nonempty directory/count/metadata coverage. Serializing the group alone would still leave unrelated host writers, while a whole-scope shared TMPDIR would still permit other suite groups to interfere.

This is a proposed harness-only scope, not a source patch or authorization to change the current freeze. A later implementation should preserve caller environment outside the child, parallel-group isolation, the protected test group's bytes, and all existing result obligations. No tests, builds, services, reruns, deletion, source/index/config/pin mutations, or Flaky licence changes occurred here. Only files in `/tmp/codex-p9d-t88-sysfiletree-final-diagnosis` were created.

## Repair recommendation and validation boundary

The controlled evidence supports the narrow populated, per-group/per-side TMPDIR harness isolation proposed above. Scope it to SysFileTree's child launches, reuse the existing owned work-directory lifecycle, and preserve the parent environment and protected ooTest sources. Put at least one stable regular file and one directory inside that private TMPDIR before launch, with runner logs and diagnostics outside it, to retain nonempty count, type, and metadata coverage. No runtime matching change, assertion relaxation, skip, or Flaky licence is indicated by these results.

Relevant later proof should check both child environments receive distinct private paths, the parent TMPDIR survives unchanged, the seeded directory is nonempty, and the unchanged group passes on both interpreters. A negative harness control should demonstrate that omitting the isolation exposes a controlled shared-directory mutation while the isolated case remains unaffected, without depending on host timing. Existing suite fixture/diagnostic tests should continue to preserve raw failure channels and process bounds, and the controller must still decide how to resume the full suite gate. Isolation removes external and other-group writers but does not promise an atomic filesystem snapshot if the same test deliberately mutates its own temporary directory.
