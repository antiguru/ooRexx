# Arithmetic attribution

The completed three-round comparison reports an 8.8a arithmetic median increase of +0.34824337% after subtracting libc and the loader. Existing round-one profiles attribute 53,500,000 new self instructions to `whole_value` and 13,500,000 fewer self instructions to `arith_general_body`, for a net increase of 40,000,000 instructions. [Focused aggregates](focused-aggregate.json) sum the self-cost rows across source-file entries, and [commands.json](commands.json) records the annotation commands, profile hashes, statuses, and source hashes. These annotations read existing profiles and execute no interpreter or additional benchmark profile.

The compiler inlined `pow` and `as_whole` under `arith_general_body`, so neither receives an independent function total. `max_value_for_digits` is inlined within `whole_value`, and its `max = max * 10 + 9` source line receives 4,000,000 instructions in the a+b annotation. Source annotations retain unidentified-line counts, and inclusive totals overlap their callees, so the focused aggregate uses self counts rather than adding inclusive totals. [Base source annotation](base-source.stdout), [a+b source annotation](ab-source.stdout), and [focused rows](focused.tsv) preserve those attribution limits alongside the evidence.
