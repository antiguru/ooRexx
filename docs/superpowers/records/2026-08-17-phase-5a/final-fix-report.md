## H1 -- the lock

### What it was

`RexxClass::liveGeneral` sets `REXX_DEFINED` on every class in the image under `PREPARINGIMAGE`
(verified: `classes/ClassClass.cpp:134` is the function, `:138` the `PREPARINGIMAGE` test, `:140`
`package = TheRexxPackage`, `:142` `setRexxDefined()` -- the two halves the plan's Task 21 row names,
in one arm). This crate carried the package half across the Task 21 / Task 23 boundary and not the
flag half, so the classes the interpreter's own `.orx` library declares were open to all five class
mutators.

Measured before the fix, in a fresh directory, both engines:

```rexx
say .Alarm~isA(.Comparable)
.Alarm~inherit(.Comparable)
say .Alarm~isA(.Comparable)
```

* oracle: rc **158**, stdout `0`, stderr the `INHERIT` frame and
  `Error 98.985:  User additions are not allowed to the REXX language classes.`
* crate, `ir` and `tree-walker`: rc **0**, stdout `0` and `0`, stderr empty.

### The fix

`Interp::install_class` (`rust/crates/rexx-exec/src/lib.rs:5257`) flags each class it creates while
`Interp::library_bootstrap` is true. Set at creation rather than by a sweep once the bootstrap
closes, which is the reason `native_classes::build` gives for setting it beside each `define_class`:
a sweep's only source of classes is a `HashMap`, and `Interp::package_classes` is one too.
`dispatch::rexx_defined_lock` is already open while `library_bootstrap` is true, so the prologue's
own `~inherit` clauses still run -- against classes that now carry the flag.

## `rexxcps` and its missing second size

Asked for while the sitting ran. **It is cheap, and there is one trap in it.**

`Workload::classify` scans a program for lines whose trimmed text starts with `n = ` and parses the
rest as an integer: none makes the workload `Fixed`, exactly one makes it `Scaled` with that value as
the bound, more than one is an error. `rendered` then runs `bound / 2` and `bound` and differences
them, which is where `fixed` and `per_pass` come from. `bench-rexxcps/rexxcps.rex` has no such line
-- it has `count=200` and `averaging=100` -- so it is `Fixed`, runs at one length, and has no
decomposition. That is deliberate: `lib.rs`'s `rexxcps_path` doc and `bench-rexxcps/README.md` both
say it is kept out of `bench-programs/` because it is reported on its own terms and has no
`n = <digits>` line.

**The trap.** The body whose passes matter runs `count * averaging` = 20,000 times, and the harness
takes the bound as the pass count. Renaming `count` to `n = 200` would make `per_pass` mean "per 100
passes of the 1000-clause body", silently, because `averaging` would still multiply it. `fixed` would
be unaffected -- it is the intercept -- but `per_pass` is the figure this phase quotes.

**What it would take, avoiding the trap**, is two lines in `bench-rexxcps/rexxcps.rex`:

```rexx
n = 20000
averaging=100
count=n/averaging
```

Then the bound the harness reads *is* the true pass count, `per_pass` is genuinely per
1000-clause pass, and the large length reproduces exactly today's work (200 x 100), so every
committed `rexxcps` figure stays comparable -- which is the property `rendered`'s own doc says
keeping the committed bound as the large size exists to preserve. The program's self-report survives
too: `thousand=innertime/count` divides by whatever `count` is, so the clauses-per-second figure is
right at either length; only the `Averaged:` line's first number changes, and it changes only in the
copy `rendered` writes into the arms workdir, never in the committed file or in what
`rexx-bench-suite` runs.

**Costs, stated rather than waved at.** The small length adds about half of `rexxcps`'s work to every
sitting, and `rexxcps` is the slowest axis. `bench-rexxcps/README.md`'s "count and averaging are
constants" sentence would need a clause saying `rexx-arms` renders a halved copy. And the file's
provenance -- the 1000-clause body is REXXCPS 2.2 verbatim -- is untouched by this: `count` and
`averaging` are already this repository's, which is what "canonicalised" means there.

**I did not make the change.** It edits the benchmark program on which the axis's committed figures
were taken, in a fix round whose subject is a lock, and the brief asked what it would take rather
than for it to be done. The asymmetry is real either way: `rexxcps` is the most realistic workload in
the guard and the only axis whose per-pass cost the decomposition cannot see.

## Concerns

1. **I shipped a wrong environmental diagnosis in a report.** The sitting is taken now, but the first
   report said the machine could not count two hardware events, which would have retired the
   measurement for anyone who read it. The observation was real and the mechanism was invented. It
   was caught because the reproduction was in the report; it would not have been caught otherwise.
2. **H1 is measured on the class side only.** `~new` is 5b's, so every check here is a class-object
   mutation. Whether the same gap reaches instance behaviour is not a question this branch can be
   asked, which is the review's own stated limit and not a new one.
3. **The non-public library classes have no differential witness.** The only route to them is
   `Package~classes`, refused at rc 120. The in-crate assertion is the whole instrument, and it will
   stay the whole instrument until that message is implemented.
4. **M4 is recorded, not resolved.** The user-visible refusal still names Phase 7 for both spellings
   of `::ATTRIBUTE ... EXTERNAL`. Narrowing it to the spelling that really is Phase 7's is a
   behaviour change with a gate row behind it, and the brief ruled out closing the row by re-filing
   it. The tree now says where the two readings disagree; it does not make them one.
5. **M2's figures are wall clock on an unpinned machine.** No CPU affinity, an oracle built
   `RelWithDebInfo -O2 -g`, and other work possible on the box. The mins are interleaved across
   three rounds, which is what makes the ~20 ms gap safe to state; the medians should not be quoted
