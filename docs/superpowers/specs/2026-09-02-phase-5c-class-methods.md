# Phase 5c: the documented per-class method sets

**Status:** draft, 2026-09-02. Continues the Phase 5 object-model spec's numbering; new decisions
here are **D70** onward (5b ended at D69).

**Depends on:** 5b, closed at `6656d5a4f`. 5b's instance construction is what makes a per-class
method set reachable at all.

---

## What this document adds

5b landed instances. 5c lands the **methods the reference guide documents on each class**, which is
gate table C's largest row kind and the phase's whole subject.

**The size, measured 2026-09-02 at `2ca6e53f4`:**

| | |
|---|---|
| method rows in gate table C | **1347** |
| of those, `covered` | 794 |
| of those, `not-covered` | 546 |
| of those, `unreachable` | 7 |
| classes carrying a `not-covered` row | 23 |
| **of those, 5c's after the 5d split** | **452 rows over 20 classes** |

**This phase must not be 1347 steps, and the row count is the wrong unit for planning it.** The rows
are a *measurement*, and they are already generated. The work divides by **mechanism**, and this
document's job is to name the mechanisms so a plan can carry one task per mechanism rather than one
per row.

## D70. `not-covered` → `covered` is the progress measure, not row agreement

**546 of the 1347 rows can be made to agree without implementing anything.**

The 23 classes with `not-covered` rows are blocked at the probe's constructor, and **the oracle
refuses that constructor too**. Measured, three descriptors, from a fresh directory:

```
say .String~new           rc=163  Error 93
say .String~new('abc')    rc=0    abc
say .WeakReference~new    rc=163  Error 93
say .TimeSpan~new         rc=163  Error 93
```

Every one has the oracle at rc 159/163/168 and never at rc 0. So matching those refusals turns 546
rows green **while `.String~new('abc')~length~upper` remains unimplemented** — the oracle already
answers that with `3 ABC`.

**Two different sets of 23 are in play and they are not the same set.** The gate's report groups by
*unanswered probe* and `class-methods.txt` groups by *`not-covered` status*; both count 23 classes,
but the gate's set contains `Pointer` and not `Singleton`, and the file's set the reverse. The
oracle evidence above was gathered over the gate's set, so `Singleton` was measured separately to
close the gap — `.Singleton~new` is rc 163 `Error 93`, and the claim holds for the file's set too.
**This document's figures are `class-methods.txt`'s throughout**; a plan quoting the gate's
`unanswered` counts is quoting a different measurement.

**The tree already says so and this decision only makes it binding.** `class-methods.txt` carries
the reason per row (`no construction program is committed; a bare ~new raises 93.903 on the
oracle`), and `class-set.txt`'s header states the escape hatch:

> `covered` is a class a bare `~new` constructs, **or one opted in with a committed construction
> program — none is committed today.**

The figures in this section are the whole 546, before the 5d split; 5c owns 452 of them and the
argument is the same for either number.

**So 5c's criterion is the transition `not-covered` → `covered`, which is a claim that a
construction program is committed, and cannot be moved by matching a refusal.** Row agreement is
reported under it, never instead of it. This is D65's "reported, not gated" made specific, and it is
the [[gate-criteria-failure-modes]] shape: a criterion that is achievable and worthless.

## D71. The unit of work is a table row, not a method

Method implementations reach the interpreter through **one table** — `dispatch.rs`'s native-entry
list, `(class, method, Arity, fn)`. Measured at `2ca6e53f4`: **59 entries across 10 classes**, of
which String has three (`LENGTH`, `REVERSE`, `UPPER`).

A plan that adds 5c's 452 methods one at a time is a plan with 452 review surfaces. A plan that adds
**one adapter per mechanism plus a table** has one review surface per mechanism, and the table is
data that `corpus/gate-tables/native-entries/` already gates.

**Every task below states its adapter and its table. A method that needs its own function body is
that task's exception and must be listed as one**, so that a reader can count the exceptions rather
than trust that there were few.

## The mechanism set

Derived by intersecting `class-methods.txt`'s `not-covered` names against what the crate already
implements. String is the worked case because it is the largest and because every mechanism appears
in it: **135 `not-covered` rows — 118 instance, 17 class — over 132 distinct case-folded names.**

The five String mechanisms partition those 132 exactly:

```
M2 BIF-backed  49    M3 operators  34    M4 caseless  15
M5 char-class  12    M6 remainder  22        sum = 132
```

**The partition is checkable and the plan should re-derive it rather than copy it.** It is stated
here because a task list built from a number nobody recomputed is how a phase acquires a row it
never implements.

### M1 — construction programs

20 classes, one committed program each, arguments taken from the book's own syntax for that class's
constructor. **No behaviour change; it is what makes every later task measurable.** Must land first.

`String` is one line. The count per class, from `class-methods.txt`, with 5d's three excluded:

```
String 135  TimeSpan 57  CircularQueue 49  Package 40  Class 32  RexxInfo 28
Message 21  Method 20  RexxContext 15  Routine 11  StackFrame 10  Supplier 8
Alarm 7  Ticker 6  VariableReference 4  WeakReference 2  InvertingComparator 2
ColumnComparator 2  CaselessColumnComparator 2  Singleton 1
```

**Some of these classes are documented as having no public constructor.** `class-set.txt`'s
`unreachable` status already exists for that case and is grounded in a sentence of the reference
re-read at its cited line on every run. A class that cannot be constructed gets that status with its
sentence, **not** a construction program invented to fit.

### M2 — the BIF adapter

**49 of String's 132 documented instance names are BIFs the crate already implements**:

```
ABBREV ABS B2X BITAND BITOR BITXOR C2D C2X CENTER CENTRE CHANGESTR CNTRL COMPARE
COPIES COUNTSTR D2C D2X DATATYPE DELSTR DELWORD FORMAT INSERT LASTPOS LEFT LENGTH
LOWER MAX MIN OVERLAY POS REVERSE RIGHT SIGN SPACE STRIP SUBSTR SUBWORD TRANSLATE
TRUNC UPPER VERIFY WORD WORDINDEX WORDLENGTH WORDPOS WORDS X2B X2C X2D
```

**The receiver's argument position varies per BIF and must be a column, taken from the book.**
Measured on the oracle, rc 0, both forms printed side by side:

```
s~pos('b')            = POS('b', s)              receiver is argument 2
s~lastpos('b')        = LASTPOS('b', s)          argument 2
s~wordpos('b')        = WORDPOS('b', s)          argument 2
s~countstr('bc')      = COUNTSTR('bc', s)        argument 2
s~changestr('a','Z')  = CHANGESTR('a', s, 'Z')   argument 2 of 3
s~abbrev('abc')       = ABBREV(s, 'abc')         argument 1
s~verify('abc')       = VERIFY(s, 'abc')         argument 1
s~compare('abcabd')   = COMPARE(s, 'abcabd')     argument 1
```

**Assuming position 1 would give a silent wrong answer on at least five of these**, which is this
project's worst defect class. The column is sourced from the book's syntax diagram for each method,
and the task's own control is to transpose one row and confirm exactly that row reddens.

### M3 — the operator adapter

34 of String's documented names are operators the interpreter already implements and reaches through
`apply_binary`:

```
+ - * / // % **  = == \= \== <> ><  < <= \< << <<= \<<  > >= \> >> >>= \>>
& && | \  || ?  []  (abuttal) (blank)
```

One adapter routing a method send to the operator the book names, plus a table. **The book's own
member entries are the mapping**; the operator's implementation is not this task's subject and must
not be modified by it.

### M4 — the caseless family

The `CASELESS*` names are each their case-sensitive sibling with a folding flag:

```
CASELESSABBREV CASELESSCHANGESTR CASELESSCOMPARE CASELESSCOMPARETO CASELESSCONTAINS
CASELESSCONTAINSWORD CASELESSCOUNTSTR CASELESSENDSWITH CASELESSEQUALS CASELESSLASTPOS
CASELESSMATCH CASELESSMATCHCHAR CASELESSPOS CASELESSSTARTSWITH CASELESSWORDPOS
```

**A sibling that does not exist yet is M6's, not this task's** — `CASELESSCONTAINS` cannot be a flag
on `CONTAINS` until `CONTAINS` exists. The task states which of the 15 had a sibling and which
waited.

Folding is **not** `to_ascii_uppercase` by assumption: what the oracle folds is a measurement, and
[[oorexx-unicode-design-space]] records that "character" is four things here. Measure it.

### M5 — the character-class family

Class-arm predicates and constants, one driver over a byte-class table. The twelve:

```
ALNUM ALPHA BLANK CR DIGIT GRAPH NL NULL PRINT PUNCT TAB XDIGIT
```

Note these are the **class** arm — `.String~alnum`, not `'abc'~alnum`. Measured: `'abc'~alnum` is
`Error 97, Object method not found` on the oracle. The arm column in `class-methods.txt` is
authoritative and a probe written against the wrong arm measures nothing.

**`BLANK` and `(BLANK)` are two different methods and a name-keyed table will merge them.** They
differ only by parentheses, sit on different arms, and are documented in different sections:

```
String  blank    class     mthStringBlank                  fundclasses.xml:5213
String  (blank)  instance  mthStringConcatenationMethods    fundclasses.xml:5919
String  (abuttal) instance mthStringConcatenationMethods    fundclasses.xml:5919
```

`blank` is this family's predicate; `(blank)` is M3's blank concatenation operator. The first draft
of this document's own partition double-counted it and summed to 133 over 132 names. **Key every
table by `(class, name, arm)`, never by name**, and let the sum check catch it when you do not.

### M6 — String's genuine remainder

**This is the honest count of String's real work: 22 of 132.** The task lists each with its

## D72. The native-entry table is sliced per mechanism, not per class and not flat

**Flatness costs nothing at run time and the question is only review and merge.** `NATIVE_METHODS`
is iterated **once, at startup**, into a `HashMap<MethodId, NativeEntry>`; no dispatch touches the
list. Its two startup panics already reject a row naming an unregistered class or a method the
class's behaviour does not answer, and both keep working under any of the shapes below because they
iterate the chain rather than the array.

| shape | what it buys | what it costs |
|---|---|---|
| **A. one flat list** (today) | one place; `git diff` shows every addition | ~500 lines in `dispatch.rs`, and all nine tasks edit one span |
| **B. per-class slices** | locality matching the book's organisation | the tasks are per *mechanism* and cut across classes, so each still touches many files |
| **C. per-mechanism slices, chained** | one file per task: adapter and table together | "what does String answer" becomes a query rather than a read |
| **D. generated from a data file** | checkable against the book in both directions, like `class-methods.txt` | the book names no implementation, so the `fn` binds by string through a macro — a typo becomes a runtime panic instead of a compile error |

**C.** It is the only one that makes D71's unit — one adapter plus one table — also the unit of
review and of the file system, and nine implementers working in parallel then never edit the same
file. The consumer already reads `NATIVE_METHODS.iter().chain(extra)`, so chaining more slices is
the shape that exists rather than a new one.

B's locality is recovered by a test, not by the layout: assert that the union of the slices is
exactly what `class-methods.txt` marks implemented, which is a check the tree wants regardless.

**A compile-time map was considered and is not what this table wants.** `phf` and `phf_codegen` are
in the offline cache, so a perfect hash over `(class, method)` is available — but the startup loop's
cost is the registry lookup that mints each `MethodId`, not the hashing of the string keys, and
dispatch never reads the list. **The map worth changing is the other one**: the runtime
`HashMap<MethodId, NativeEntry>` is hashed on **every** native dispatch, and `MethodId` is a
`u32` minted in monotonic order, so an index into a `Vec<Option<NativeEntry>>` would remove that
hash entirely. Sampled at 2.42% of `bench-programs/dispatch.rex` under `hash_one::<&MethodId>`.
**Neither is 5c's work** — both belong to the deferred performance round — and D72's slicing is
chosen so as not to preclude either: it changes what feeds the loop, never what the loop builds.

## D73. `unreachable` classes are deferred, and guarded against becoming reachable

**Deferred:** `Buffer` and `Pointer`, seven rows, both grounded in the same sentence of the
reference — `utilityclasses.xml:429` and `:6910`, "can only be created using the native code
application programming interfaces." All six `Pointer` rows and the one `Buffer` row carry the
status; neither class has a row with any other status.

**But `unreachable` is a claim about today that 5c could falsify by accident.** A phase that adds
constructors, `~of`-style class methods, or a `makeArray` that hands one back could make either
class constructible without anyone deciding to, and the status would then be a false sentence
sitting in a generated file that nothing re-checks against behaviour.

So the deferral comes with a guard: **for every class `class-set.txt` marks `unreachable`, a
committed test that its documented construction route still refuses**, on both engines, with the
oracle's answer recorded beside it. The guard is derived from the status column rather than from a
list of two names, so a class that becomes `unreachable` later is guarded by existing.

**The guard must be shown to fail.** Its control is to make one of the two constructible and
confirm the test reddens — [[test-can-fail-is-not-test-adds-coverage]], and this project has shipped
a guard blind to its own subject often enough that an ungated one is not worth having.

**Phase 5e** takes whatever `unreachable` classes remain when 5d closes, if any turn out to be
reachable after all. If the guard never fires, 5e is empty and that is the good outcome.

## D74. The tightened comment policy binds this phase

**Moritz, 2026-09-01, in force since 5b closed:** a comment is *"never more than a sentence and a
short paragraph. the code speaks for itself... no results, no reasoning, no alternatives. these go
to design documents."* It tightens `rust/CLAUDE.md`'s 2026-08-27 rule rather than replacing it,
adding a length bound and naming three things now out however they are phrased.

**5c is the first phase written under it, and every M-task's adapter is exactly the shape that
tempts a long comment** — a table whose rows encode a measured mapping, with rejected alternatives
behind it. Those belong in this document or in `docs/superpowers/records/<plan>/`, and the comment
says what the adapter does.

**The destination is not optional.** Some prose in this tree is the authority on a measured shape
and deleting it destroys evidence; M2's receiver-position column is exactly that kind. Under D74 the
measurement moves, it does not evaporate.

**Already violated, in code landed 2026-09-02 after 5b closed.** `clause.rs`'s `Deadline` carries a
97-line doc comment holding a measurement table, two rejected shapes with their figures, and the
reasoning for the placement. Its content is already committed at
`docs/superpowers/records/2026-08-27-phase-5b/watchdog-report.md`, so trimming it loses nothing.
Blocks of 48, 36 and 22 lines sit beside it. **5c does not start until that file is brought under
the policy**, because a phase that begins beside a fresh violation will not enforce one.

## Handover to Phase 5d

**5d owns `File`, `Stream` and `StreamSupplier` — 94 `not-covered` rows.**

`StreamSupplier` is there for a reason found by running it rather than by grouping it. It has no
public constructor and its only construction route is a `Stream`:

```
say .StreamSupplier~new                    rc=159  Error 97   (object method not found)
.stream~new('t.txt')~supplier ~class~id    rc=0    StreamSupplier
```

So its nine rows cannot leave `not-covered` until `Stream` does, and a 5c that kept them would carry
a task it could not finish. **5d owes a ruling on whether `StreamSupplier` is `unreachable` in
`class-set.txt`'s sense** — the book calls it a snapshot of a stream, which is the shape that status
exists for, but the sentence has to be cited and re-read, not paraphrased.

`Supplier` itself stays in 5c: it is a different class, `.Supplier~new` is documented at
`utilityclasses.xml:9956`, and its rows do not depend on a stream.

## The gate

Criteria, each with the instrument that measures it:

1. **`not-covered` count falls to its planned target**, `class-set.txt` and `class-methods.txt`
   re-derived by `rexx-extract-docs` and compared in both directions by `tests/extract_docs.rs`.
   D70 makes this the criterion; a plan that reports row agreement in its place is measuring
   nothing.
2. **Gate table C's 5c rows agree**, under `REXX_PHASE_GATE=5c`, with `CLOSED_PHASES` extended —
   and with the assertion 5b's review added (`every_closed_phase_this_table_owns_rows_for_is_gated`)
   still passing, so the flip cannot be silently reversed.
3. **The five gates each 0**, and the corpus headline at its full count.
4. **Every mechanism task's table has a transposition control** that reddens exactly its own row.
   M2's receiver-position column is the one this exists for.
5. **`bench-programs/alloc.rex` and `heapshape.rex` run.** They are rc 120 today on `.Array~of` and
   `.Directory~new`, so the **allocation and heap-shape axes are unmeasured** — the two an
   object-model phase is most likely to regress. Both methods are already recorded as blocking 5b
   witnesses (`plans/2026-08-27-phase-5b.md:730`, `:848`, `:944`). Landing them early in 5c
   unblocks deferred work and restores the instrument before the phase's bulk lands.

6. **The `unreachable` guard passes and has been shown to fail** (D73): every class
   `class-set.txt` marks `unreachable` still refuses its documented construction route on both
   engines, and the control that makes one constructible has been run and reddened it.

**Not a criterion:** the count of method rows that agree, for D70's reason.

## Risks

| risk | why it bites | mitigation |
|---|---|---|
| 452 rows go green with no implementation | the probes die at the constructor and the oracle refuses it too | D70 makes construction the criterion |
| the BIF adapter assumes receiver position 1 | five measured BIFs put it at 2, one at 2-of-3; the result is rc 0 with a wrong answer | position is a book-sourced column with a transposition control |
| a task grows to one step per method | 452 rows, nine mechanisms | D71: one adapter and one table per task; exceptions listed and counted |
| the perf axes stay dark through an object-model phase | `alloc.rex` and `heapshape.rex` are rc 120, and per-step thresholds already hid a +32.58% cumulative drift once | gate criterion 5 |
| construction programs invented to fit | a class documented as having no public constructor | `unreachable` status, grounded in a re-read sentence |
| an `unreachable` class quietly becomes constructible | a new class method or `makeArray` can hand one back without anyone deciding to; the status is then a false sentence nothing re-checks | D73's guard, derived from the status column and with a run control |
| a figure quoted from the gate's report instead of the file | the two group differently and their 23-class sets differ by one element each way | D70 names `class-methods.txt` as this document's source throughout |

## Open for the plan

1. **Are M2..M6 five tasks or one?** They share String and a review of all five together is one
   reading of one class; five tasks is five sets of gates. The merge argument (D72) points at five,
   the coherence argument at one.
2. **Task order beyond M1 first.** M4 depends on M2 and M6 for its siblings, which the plan has to
   sequence or the caseless task blocks.
3. **Whether the three comparators and `VariableReference` are constructible at all.** They are
   `not-covered` today, which carries no claim about the oracle; nobody has run them. If any is
   documented as native-only it belongs under D73's guard rather than M1's construction list.
