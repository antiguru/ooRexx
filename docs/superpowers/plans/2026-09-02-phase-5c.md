**Scope:** 903 rows — table C's 868 not-yet-agreeing 5c rows and table D's 35.

## The premise, in one paragraph

Table C's method probes are `hasMethod` readbacks; a method is never sent. So a row agrees when the
probe **constructs an instance** and the class **answers the documented name set** — not when the
method works. Implementing method bodies is real work that this phase's instrument cannot see, and
it is out of scope here. Every one of the 868 is construction-blocked on this crate today.

## Task 1 — the construction route, and surface B

**First, because every other task depends on the route existing.**

`gate_table_c.rs:815` states the obligation in its own words: *"Every instance-arm program here opens
with a bare `~new`, and there is no route to a committed construction program because none exists to
route to. The task that commits the first one has to add that route here in the same change; what it
must not do is flip a class to `covered` and leave the derived probe on a bare `~new` that raises."*

Build that route, and use it for surface B's eight classes, whose `~new` needs arguments. `.TimeSpan`
is the worked case: `.TimeSpan~new(1)` already answers `0.000001` on this crate, byte-identical to
the oracle, so its 47 rows need only the program.

`covered`'s second limb is the hand-written `CONSTRUCTION` const at
`crates/rexx-extract/src/docs/classes.rs:117`, and `status_of` reaches `Covered` only through it —
**so the status transition is a string edit and is not by itself evidence of anything.** Whatever
this task builds must make the transition mean the probe constructs. Say in the report how you made
that true, and what would still let someone flip a class without it.

**Done when:** the route exists and is exercised by at least surface B's eight; each of those eight
probes is rc 0 and matches the oracle on three descriptors, both engines; and the control — flip a
class to `covered` without a program — has been run and is shown to fail.

## Task 2 — surface A, the 24 constructors

`Bag Class Directory EventSemaphore IdentityTable List Message Method MutableBuffer MutexSemaphore
Package Pointer Queue Relation RexxContext Routine Set Stem StackFrame String Supplier Table
VariableReference WeakReference` — the distinct `~NEW` blockers behind 30 probes.

**`Pointer` is `unreachable` (D73) and must not get a constructor.** It is in this list because its

**`String~new` is here**, and `alloc.rex` needs it — see Task 4.

**Done when:** each constructor's probe is rc 0 and matches the oracle on three descriptors, both
engines; the classes that should still refuse still do; and the not-yet-agreeing count in table C is
reported before and after.

## Task 3 — surface C, the classes with no `~new`

`RexxInfo` `RexxContext` `StackFrame` `VariableReference` — **57 rows.** All four raise on `~new` and
all four have a working Rexx-level route, measured on the oracle:

```
.context~class~id                 ->  RexxContext
.context~stackFrames[1]~class~id  ->  StackFrame
.RexxInfo~class~id                ->  RexxInfo
x = 5 ; say (>x)~class~id         ->  VariableReference
```

**These are not D73's `unreachable`.** `classes.rs`'s `UNCONSTRUCTIBLE` already carries all four as
`Status::NotCovered`, on the rule that a sentence naming a Rexx-level route makes a different claim
from one that does not. Read that doc comment before classifying anything.
