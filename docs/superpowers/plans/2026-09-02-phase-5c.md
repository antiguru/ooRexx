## The premise, in one paragraph

Table C's method probes are `hasMethod` readbacks; a method is never sent. So a row agrees when the
probe **constructs an instance** and the class **answers the documented name set** — not when the
method works. Implementing method bodies is real work that this phase's instrument cannot see, and
it is out of scope here. Every one of the 868 is construction-blocked on this crate today.

## Global constraints

Unchanged from the first version and binding on every task; a brief does not repeat them.

  is how the first version of this plan reported 59 native entries where there are 78 in
  `NATIVE_METHODS` plus a second table, `NATIVE_CLASS_METHODS`.
* A gate run does not survive the turn that starts it: statuses to a file, a waiter that exits on the
  process vanishing, read them in the turn you commit. Tree hash before the first gate and after the
  last.
* `git commit -F <file>`, paths named explicitly. Never `git add -A`, amend, bare `git stash`, `rm`

* **The scratchpad is a RAM disk; build trees do not go in it.** `/tmp` is tmpfs, 63 GB against the
  machine's 124 GB of memory, and a `git archive` extract with its own `CARGO_TARGET_DIR` costs
  2-5 GB. Forty-one GB of them filled it once this phase and silently killed an extract mid-launch.
  Small files -- probes, logs, statuses, reports -- stay in the scratchpad; **any isolated build tree

  ~690 GB free and outside every git worktree. Check `df -h /tmp` first and say what you created.
* **Never delete anything yourself, including your own scratch directory.** An `rm` of any shape
  raises a permission prompt nothing in a subagent context can answer, and it parks you indefinitely
  while you still report as running -- that cost three hours this phase. Name what you created; the
  controller sweeps it.
* **Kill what your probes start, and confirm with `kill -0`.** A probe constructing an `Alarm`, a
  `Ticker` or anything else that schedules leaves a live interpreter behind: two ran for eight hours
  this phase, one on an 86400-second alarm.
* **Never wait on a job with `pgrep -f <pattern>`** -- it matches the polling shell's own command

### Working on one worktree (ruled 2026-09-03: no worktree-per-task)

* **One agent holds the tree at a time.** The controller dispatches the next task only after the
  previous one has committed and its gates have been read -- not when it reports, and not when it
  looks finished. Both of this phase's collisions were a dispatch over a live agent.
* **A ruling makes a finished agent live again.** "Reported and went idle" stops being true the
  moment the controller sends something to act on; that is a re-dispatch and it takes the tree back.
* **If two agents share the tree anyway they own disjoint paths**, and a second agent records into a
  shared document without touching the first's working copy: `git hash-object -w` to build a blob of
  HEAD-plus-your-own-block, then `git update-index --cacheinfo` to place it -- **this writes the
  index and never the worktree** -- then verify your block is in HEAD, theirs is not, and theirs is
  still unstaged. `git add <shared file>` is what destroys work here, not editing.
* **Pin your files as the last thing before you stop**, never before your final edit, or the pin
  covers your own later work and reports a collision that did not happen. Compare with
  `sha256sum -c` or `cmp`, never by reading a truncated hash -- `19927296` and `1992729e` agree for
  seven characters.
* **Attribute a changed file with a three-way comparison, never HEAD-against-worktree**, which
  cannot distinguish "someone captured my draft" from "I committed that draft myself".
  `git diff --numstat <mine> <theirs> -- <file>` showing zero deletions settles it. A **false**
  collision costs more than a missed one: it triggers an escalation and `git` surgery on a tree that
  was fine.
* **No `rm` with a glob or a computed path.** Its extent depends on the filesystem at run time, so it
  cannot be approved by reading the command -- and in a subagent that prompt cannot be answered at
  all, so it deadlocks you while you still report as running. A specific named literal path you
  created yourself raises no prompt and is fine. Name anything large you leave behind; the controller
  sweeps it.
* **A stalled agent and a working one are told apart by two signals together**: no file written for a
  long interval, **and** no `cargo` or `rustc` process alive. Either alone is inconclusive.

**The heap-shape axis was measuring a graph a thousand times too small on this crate, and that is the

oracle's own figure barely moves between the two, which is what identifies whose graph changed. The
program's header already carried the *interning* form of this trap; the handle form is the same trap
by a second route, and the slot strings are now wide enough for both. `phase-4d-gate.md`'s criterion

arm has met it -- the arm it was checked against was `crates/rexx-core/benches/heap.rs`, which
allocates `Body::Text` directly and was never affected.

**The figures at head**, `rexx-run` sha256 `983ed01bf5bbb25d77981f05ab81d9b9462d5f7ce63323453fbff207b2ce1495`,

| axis | figure | oracle | this crate | ratio |
|---|---|---:|---:|---:|
| `alloc` | wall | 1.14 s | 3.64 s | 3.19x slower |
| `heapshape` | `build_seconds` | 0.20786 | 0.355455 | 1.71x slower |
| `heapshape` | `gc_pause_seconds` | 0.017411 | 0.014672 | **0.84x** |

`native_identity_hash`'s own doc. `RexxObject::identityHash` is `((uintptr_t)this) ^ UINTPTR_MAX`
