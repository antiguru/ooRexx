## Global constraints

These bind every task and a task's brief does not repeat them.

* **D74 is in force.** A doc comment is one sentence plus at most a short paragraph, saying what the
  item is and the one property the code does not show. **No results, no reasoning, no alternatives.**
  Those go in this plan, in the spec, or in your report under
  `docs/superpowers/records/2026-09-02-phase-5c/`. `964dc68ba` is the worked example of the trim.
* **`class-methods.txt` is the authority and is generated.** No method name enters from anywhere
  else and none is dropped. A disagreement with the book is a change to `rexx-extract-docs`, never
  to the file.
* **Do not quote the gate report's `unanswered` counts as if they were `not-covered` counts.** They
  group differently and their class sets differ; the spec's D70 records how.
* Three descriptors read separately, never `2>&1`; both engines (`REXX_ENGINE=ir`,
  `REXX_ENGINE=tree-walker`).
* Oracle probes from a **fresh empty directory** — the scratchpad root is on the oracle's external
  routine search path. Wrap every oracle run as
  `( ulimit -v 1048576; LD_LIBRARY_PATH=/home/moritz/dev/repos/ooRexx/build/lib /home/moritz/dev/repos/ooRexx/build/bin/rexx FILE )`.
* Never run a program in `rust/corpus/oracle-crashes.txt`, and never construct one of those shapes.
* **No `unsafe`.** The workspace lint is `deny` and it is Moritz's decision per site. Stop and say so.
* `oodocs/`, `ootest/` and `/home/moritz/dev/repos/ooRexx/interpreter/` are **read-only**.
* A gate run does not survive the turn that starts it: statuses to a file, a waiter that exits on the
  process vanishing, read them in the turn you commit.
* Tree hash before the first gate and after the last, covering untracked files' bytes.
* Commit with `git commit -F <file>`, naming paths explicitly. Never `git add -A`, never amend,
  never a bare `git stash`, never `rm` with a star glob, never `git checkout --` on a file you have
  edited — copy to the scratchpad and restore from the copy. Confirm `Cargo.lock` is absent from the
  staged set.
* Report to `.superpowers/sdd/2026-09-02-phase-5c/task-N-report.md`. **Say plainly what you did not
  do.**

## Task 0 — restore the two dark benchmark axes

**Subject:** `.Array~of` and `.Directory~new`. Neither class is in the 20; this is not an M-task.

`bench-programs/alloc.rex` and `heapshape.rex` are rc 120 today, so the **allocation and heap-shape
axes have never been measured** — the two an object-model phase is most likely to regress, and
per-step thresholds already hid a +32.58% cumulative drift once. **First, so the instrument exists
before the phase's bulk lands.**

Both methods are already recorded as blocking 5b witnesses
(`plans/2026-08-27-phase-5b.md:730`, `:848`, `:944`); building them unblocks that deferred work too.

**Done when:** both programs are rc 0 and their output matches the oracle on three descriptors, both
engines; `rexx-arms` reports a figure for each against the pinned baseline; the 5b witnesses those
two methods blocked are either built or listed with the reason they still are not.

## Task 1 — M1, construction programs, and D73's guard

**Subject:** 20 classes, one committed construction program each, arguments from the book's own
syntax. Plus the guard for `Buffer` and `Pointer`.

`class-set.txt`'s `covered` status already has the "opted in with a committed construction program"
arm and nothing has ever used it. **Find how that arm is meant to be spelled before designing one**
— it is `rexx-extract-docs`'s `src/docs/classes.rs` that writes the column, and
`tests/extract_docs.rs` that compares both directions.

**Three of the 20 have not been run against the oracle at all** — the three comparators and
`VariableReference`. `not-covered` carries no claim about the oracle. Measure each before writing a
construction program for it: one documented as native-only belongs under D73's guard instead.

**D73's guard**, in the same task because it shares the status column:

* For every class `class-set.txt` marks `unreachable`, assert its documented construction route
  still refuses, on both engines, with the oracle's answer recorded beside it.
* **Derive the population from the status column, not from a list of two names**, so a class that
  becomes `unreachable` later is guarded by existing.
* **Run the control**: make one of the two constructible and confirm the guard reddens. A guard that
  has not been shown to fail is not worth having, and this project has shipped several.

**Done when:** the `not-covered` count has fallen by construction alone, with the fall attributable
per class; the guard passes; the control has been run and is recorded with its transcript.

## Task 2 — M2 through M6, String, as one task

**Ruled by Moritz 2026-09-02: the five String mechanisms are one task, not five.** They share one
class and one construction program, and a reviewer reading them together reads one class once.

**135 `not-covered` rows over 132 distinct case-folded names**, partitioning exactly:

```
M2 BIF-backed  49    M3 operators  34    M4 caseless  15
M5 char-class  12    M6 remainder  22        sum = 132
```

**Re-derive that partition rather than copying it.** A task list built from a number nobody
recomputed is how a phase acquires a row it never implements.

Per D72, each mechanism gets its **own file carrying its adapter and its table**, chained into
`NATIVE_METHODS` at the existing `.iter().chain(extra)`. The two startup panics keep validating
every row and must not be weakened.

### The two hazards this task exists around

**M2's receiver position varies per BIF and is a book-sourced column.** Measured:

```
s~pos('b')            = POS('b', s)              receiver is argument 2
s~lastpos('b')        = LASTPOS('b', s)          argument 2
s~wordpos('b')        = WORDPOS('b', s)          argument 2
s~countstr('bc')      = COUNTSTR('bc', s)        argument 2
s~changestr('a','Z')  = CHANGESTR('a', s, 'Z')   argument 2 of 3
s~abbrev('abc')       = ABBREV(s, 'abc')         argument 1
s~verify('abc')       = VERIFY(s, 'abc')         argument 1
s~compare('abcabd')   = COMPARE(s, 'abcabd')     argument 1
```

Assuming position 1 is a **silent wrong answer** — rc 0 with different bytes, this phase's worst
class. **The control is to transpose one row's position and confirm exactly that row reddens.**

**Key every table by `(class, name, arm)`, never by name.** `BLANK` and `(BLANK)` are different
methods on different arms in different sections (`fundclasses.xml:5213` and `:5919`); the spec's own
first partition merged them and summed to 133 over 132. A sum check against the re-derived partition
is what catches it.

**M4 is sequenced last within this task.** A `CASELESS*` method is its sibling plus a fold flag, and
some siblings are M6's. **What the oracle folds is a measurement, not `to_ascii_uppercase` by
assumption** — see the Unicode design space; `class-methods.txt` does not answer it.

**M5 is the class arm.** `.String~alnum`, not `'abc'~alnum`; measured, the latter is `Error 97` on
the oracle. A probe on the wrong arm measures nothing.

**Done when:** all five tables are committed with their adapters, the partition is re-derived and
sums, the transposition control has been run and reddened exactly one row, and every name the task
did **not** implement is listed with its book citation.

## Task 3 — M7, reflection

`Package` `Method` `Routine` `Class` `RexxContext` `StackFrame` `RexxInfo` `Message`. **177 rows**,
the largest group.

`.Message~new` is here and 5b explicitly handed it over
(`plans/2026-08-27-phase-5b.md:173`). These classes reflect over interpreter state the crate already
holds, so the risk is not construction but **answering from the wrong instance** — a `StackFrame`
describing the probe's own frame rather than the one asked for. Prefer probes whose answer differs
per frame.

## Task 4 — M8, time

`TimeSpan` `Alarm` `Ticker`. **70 rows.**

**These are the phase's non-determinism.** An `Alarm` fires on a clock and a `Ticker` repeats;
differential comparison against the oracle needs shapes whose output does not depend on scheduling.
If a documented behaviour cannot be compared deterministically, **record it as a licensed divergence
with its reason rather than building a flaky row** — `tests/licensed_divergences.rs` is the existing
instrument and it asserts its own table's completeness.

## Task 5 — M9, collections and misc

`CircularQueue` `Supplier` `WeakReference` `VariableReference` `Singleton` and the three comparators.
**70 rows.**

`WeakReference` interacts with collection, which D59a licensed to diverge and **5c owes the
witnesses** (`specs/2026-08-27-phase-5b-instances.md:95`, `:621`, `:622`). Read D59a before writing
one: two of its four consequences are this phase's and two are not.

`Supplier` stays here; `StreamSupplier` is 5d's, because its only construction route is a `Stream`.

## What this plan does not decide

* **The order of Tasks 3, 4 and 5.** They share no code and may run in parallel or in any order.
* **Whether any of the 20 turns out to be `unreachable`.** Task 1 measures; if it finds one, that
  class's rows leave M1 and join D73's guard, and the phase's target moves. Say so rather than
  quietly absorbing it.
* **5e's contents.** It exists only if D73's guard fires or a deferred class turns out reachable.
