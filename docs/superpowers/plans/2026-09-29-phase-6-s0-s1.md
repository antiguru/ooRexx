# Phase 6, stages S0 and S1: foundations and stackless calls, implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to
> implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Split per-activity state out of the interpreter, and make Rexx-to-Rexx calls and sends run
inside one driver loop instead of recursing on the native stack, with no behaviour change and within
the performance budget, so that S2 (activities) has continuations to switch.

**Architecture:** S0 moves everything that belongs to one execution (`Interp`'s per-execution
fields, the `RootSet`'s per-activity part, the frame arena) into an `Activity` that the interpreter
holds exactly one of, and commits the instruments (benchmarks, a callgrind script, the pinned-park
counter, the derived concurrency test list). S1 makes arena offsets activation-relative, then turns
the driver into a loop that pushes a callee's frame and continues in the same iteration, first for
calls, then for sends and argument positions, then for plain DO blocks and the `Op::Exec` park
channel. Every step is behaviour-neutral: one activity exists throughout this plan.

**Tech Stack:** Rust; `rexx-core`, `rexx-exec`, `rexx-bench`; no new dependency in this plan
(`loom` and `libc` arrive with S2 and S4).

**Spec:** `docs/superpowers/specs/2026-09-29-phase-6-concurrency-design.md` (at `50adaa724`), its
reviews and spikes under `docs/superpowers/records/2026-09-29-phase-6-design/`, and the research
direction `docs/superpowers/specs/2026-09-08-concurrency-research-direction.md`. S2 to S5 get their
own plan, written against this plan's measured S1.

## Global Constraints

* **Behaviour is unchanged.** No stage of this plan adds a second activity or changes any program's
  stdout, stderr or exit status. The corpus differential stays at its current count, identical.
* **`unsafe`** stays in `rexx-api/src/ffi.rs`, `rexx-api/src/load.rs`, `rexx-core/src/bytes.rs` and
  `rexx-core/src/frame.rs`, each block with a `SAFETY:` note. `frame.rs`'s invariants change in
  Task 5; its grant is restated first, as a Section 1 decision block in the roadmap (Task 1).
* **No new dependency.** No `Op::Generic`, ever (Moritz). `Op::Clause` stays at discriminant 0
  (`ir.rs:75`; the jump-table note), and `size_of::<Op>() == 16` (`ir.rs:60`) holds.
* **No mutable process-global state.**
* **Every allocation remains a collection point**, and nothing borrowed from `Interp`, an arena or a
  `RefCell` is held across a point that could later become a driver exit (spec, P6-3 and section 5):
  new code in S1 is written to that rule even though no exit exists yet.
* **Performance rule** (spec section 7): callgrind instruction counts with glibc and ld-linux
  excluded, each build in its own target directory with a `Compiling` line; three layout controls
  per stage; every figure a **running total against the Phase 6 base commit** (Task 2 records it);
  after S0 at most +0.3% beyond the noise band on every program, after S1 at most +0.3%; wall clock
  within ±4%; a stage over budget gets at most three rounds (a round is one committed candidate
  change measured on every program), then stops for Moritz's ruling.
* **Oracle runs**: `( ulimit -v 1048576; LD_LIBRARY_PATH=/home/moritz/dev/repos/ooRexx/build/lib
  /home/moritz/dev/repos/ooRexx/build/bin/rexx FILE )` from a fresh empty directory; stdout, stderr
  and exit status compared separately; `rust/corpus/oracle-crashes.txt` read first; nothing that
  changes rxapi's persistent state.
* **Read-only**: the C++ tree, `samples/`, `build/`, `ootest/`, `oodocs/`, `testbinaries/`, `api/`.
* **Comments minimal**, never stating a set's size, no em-dashes, never dropping or re-wrapping a
  comment. Every extent claim is derived with its command committed; every negative control's
  prediction is written before it runs.
* **Gates**: `cargo fmt --all --check`; `cargo clippy --workspace --all-targets -- -D warnings` from
  an empty target directory; `REXX_CORPUS_GATE=1 memcap 8G cargo test --workspace --no-fail-fast`
  in release and in debug. Commit before a gate run and leave the tree untouched until its status
  file says finished.

## Review Focus

1. **A collection inside a newly stackless call.** A value held in a Rust local across a callee's
   frame push, which recursion used to keep on the native stack, is now unrooted when the callee
   allocates. Expect the collect-at-every-allocation stress run to stay green; Task 8 and Task 9
   each add a stress test that allocates inside the callee while the caller holds a value.
2. **Conditions and SIGNAL unwinding across stackless frames.** A SYNTAX raised three frames deep
   that is trapped by CALL ON in the outermost caller, and a SIGNAL out of a callee, must unwind the
   same frames, run the same traps and print the same traceback as recursion did. Task 8 adds
   corpus witnesses for both.
3. **TRACE output across stackless calls.** Indentation and `>>>`/`>I>` lines depend on nesting
   state that recursion kept in Rust locals. Expect byte-identical trace output; Task 8 runs the
   trace corpus and `tests/trace_oracle` against the oracle.
4. **Deep recursion.** Error 11 at the depth cap must still fire at the same depth and with the same
   message, now without native recursion. Task 8 witnesses a recursive function and a recursive send
   hitting the cap.
5. **REPLY and started messages.** Today they run synchronously or deferred; after Task 9 their
   first send and resume go through the stackless entry, and their output order must not change.
   Task 9 runs the REPLY and Message corpus programs and witnesses one of each.
