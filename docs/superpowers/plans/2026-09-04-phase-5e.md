# Phase 5e plan — `MutableBuffer` gets state

Spec: `docs/superpowers/specs/2026-09-04-phase-5e-mutablebuffer.md`. Read it first; this plan does
not restate its measurements.

**The hollowness check is already landed** at `0ef9d5064`, ahead of this work and deliberately so —
the spec's own risk section said to land it first, because both it and this phase move rows in
`corpus/method-bodies.txt` and one diff carrying both would stop being readable. So the 71
`unanswered` rows are already in the baseline, and any row this phase moves is this phase's.

BASE for Task 1 is the commit this plan lands in.

## Global constraints

Every task, no exceptions.

* **Commit before the full gate run, not after**, per `rust/CLAUDE.md`'s Gates section: fast checks
  yourself, commit code and report together with the report's gate cells left as `**G1**`–`**G7**`,
  start the suite in the background with the commit sha as the status file's first line and a
  pidfile beside it, report `committed at <sha>, gates running, statuses at <path>` and **stop**.
  The tree belongs to the gate run until its status file says `finished`.
* **Every claim gets a red control**, predicted before it is run and marked confirmed, falsified or
  unobservable. A control that varies something *about* the change proves nothing.
* **Both engines every time**: `REXX_ENGINE=ir` and `REXX_ENGINE=tree-walker` — that exact spelling.
* Three separate descriptors, never `2>&1`, `$?` captured immediately.
* Oracle runs from a fresh empty directory, wrapped as
  `( ulimit -v 1048576; LD_LIBRARY_PATH=/home/moritz/dev/repos/ooRexx/build/lib /home/moritz/dev/repos/ooRexx/build/bin/rexx FILE )`.
* **Never `git checkout -- <path>`** on a file you edited; `cp` to your scratch directory and
  restore from the copy, then `touch` it — `cp -a` preserves mtime and cargo will keep the stale
  binary.
* No `unsafe`; the workspace lint is `deny` and it is Moritz's call per site.
* Never `git add -A`; never amend; `git commit -F <file>` with paths named; confirm `Cargo.lock` is
  not staged unless the task deliberately changed it.
* **A method that exists and does nothing is not implemented** — `rust/CLAUDE.md`, and this phase
  exists because of it. Do not add a name that answers nothing to close a row.

## Task 1 — where the bytes live, decided by measurement

**Answers D80, and builds nothing that ships.**

The spec offers three shapes: an object variable in `Body::Instance`'s `pools`; a new boxed `Body`
variant carrying `Bytes` plus a capacity, on `Body::Native`'s precedent; or `NativeObject`'s
`entries` map. **`rexx-core/src/body.rs` has a width assertion and it is the constraint on all
three** — read it before proposing anything.

**First, the question nobody has asked**: `String` has its own loud rows and the crate already
carries byte machinery for `Bytes`. Find out what exists before designing. If `String`'s
representation already gives most of this, say so and the phase gets smaller.

**Measure, do not choose on taste.** Build the two live candidates far enough to run an append loop
and a length loop, and report instructions for each with the sha256 of each binary. A prototype
that is thrown away is the right outcome here.

**Deliverable:** a decision recorded in the spec as D80, with the measurement beside it, and no
production code.

## Task 2 — the constructor carries state, and `File` constructs

**The phase's reason for existing, and the smallest thing that proves it.**

Implement the chosen representation and the five methods `File~init` reaches on unix:
`~new` (already answers, but must now keep what it is given), `~length`, `~endsWith`, `~string`, and
`~delstr`. `getBufferSize`/`setBufferSize` come with them — **capacity is observable**, defaults to
256, is settable, takes the constructor's second argument, and survives an append that grows length;
the spec has the transcript.

`dispatch.rs`'s constructor doc currently says the contents "are not kept, and nothing that would
read them answers", and
`a_constructor_taking_arguments_answers_an_instance_and_refuses_its_state` asserts that pair. **Both
are now false and both are yours to correct** — the test becomes the assertion that state *is* kept.

**The witness is a corpus program**, not a test binary: `.File~new('/tmp')~name` and its neighbours,
compared byte for byte against the oracle. `corpus/README.md`'s "Two shapes work" section governs
any helper file. Name it in `corpus/unfiled.txt` until the phase closes.

**Read `MutableBufferClass.cpp` for the 256 default** rather than hardcoding what one probe showed —
the spec flags it as measured on this host only.

## Task 4 — `method-owner`, and who owns these rows now

**Answers D81.** `class-set.txt` gives `MutableBuffer` `method-owner` `5c`, and `5c` is closed. Either
re-own the rows to `5e` or leave them and rely on the method-body table.

Re-owning is preferred and it changes a committed table whose drift is itself gated, so it needs the
same control discipline as any table change: predict the row movement, run it, show the gate reddens
without the corresponding `CLOSED_PHASES` entry.

**Check first whether `5e` needs to exist as a phase id at all** — if the rows are better owned by
`5c` re-opened, or by a name that is not a phase, say so. This is a decision to take with a
measurement, not an assumption to inherit from this plan.

## Task 5 — the flip and the close

`CLOSED_PHASES` gains the phase's id if Task 4 created one. `corpus/phase-5e.txt` names the
witnesses; `corpus/unfiled.txt` ends with none of them left. **Verify the flip by running it in a
`git archive` extract with its own `CARGO_TARGET_DIR`**, before committing — 5c's flip did not work
and that is how it was found, and Task 6 of 5d found `package_requires.rs` held four tests no corpus
program could express, so **enumerate from the tree, not from this plan**.

**Expected after, stated as measurements with their commands:** every `MutableBuffer` instance row
reads `answers`; `.File~new('/tmp')~name` agrees with the oracle; the 71 `unanswered` rows are
unchanged except `File`'s 50, which move to whatever they now measure — **and that movement is a
finding to report, not a number this plan predicts.**

## The gate

Per the spec: every `MutableBuffer` instance row moves `loud` → `answers` and none moves to
`diverge`, plus `.File~new('/tmp')~name` byte-identical to the oracle as a corpus program.

**`File`'s rows are not a criterion.** They leave `unanswered` once `File` constructs, and what they
become is Phase 7's business. A task that finds them all `answers` has learned something worth
reporting; a task that *aims* at that has taken Phase 7's work.
