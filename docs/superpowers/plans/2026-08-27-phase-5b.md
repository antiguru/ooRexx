## Global constraints

they bind unchanged. The ones this plan leans on hardest:

  paragraph, and assert a load-bearing property in a test instead of describing it.

## Task 1: `~new`, `INIT`, and the instance seam

**Goal.** `corpus/gate-tables/concepts/creo.rex` and `abscla.rex` agree.

**Measured.** Both are rc 120 today, refused at `method "NEW" of class "Object" is not implemented
(Phase 5)`. Oracle for `creo.rex` is rc 0, `type a savings account` / `balance 1000.00` /
`rate 6.25`; for `abscla.rex` it is rc 158, stdout `declared AB Class`, stderr the `98.989 Class AB
is ABSTRACT and cannot be directly created.` transcript with a `Compiled method "NEW" with scope
"Object".` frame.

**What is already there, probed separately.** `Body::Instance(ScopePools)` exists and is what a class
object's own variables already use; `receiver_kind` (`dispatch.rs:1123`) refuses it with
`Err("an instance of a user class")`, which is the seam. `("Object", "INIT", Arity::Fixed(0),
native_no_op)` is already in the native table (`dispatch.rs:375`).
`~objectName`/`~objectName=`/`~string`/`~class`/`~isA` all answer for a class receiver and need only a
second receiver kind. **`~defaultName` answers for no receiver at all** -- `DEFAULTNAME` appears
nowhere in `crates/rexx-exec/src/` outside doc comments, and `.K~defaultName` is rc 120 on both
engines today against the oracle's `The K class` -- so it is built here from zero.
**Re-measure all of this.**

**Build.** `RexxClass::completeNewObject` (`ClassClass.cpp:1882`) in its four steps, in order:
`checkAbstract`, set the behaviour from the class's instance behaviour, register `UNINIT` if the
class or a parent defines it, send `INIT` with `~new`'s arguments. The registry already carries the
`UNINIT` flags (`has_uninit`, `parent_has_uninit`) that step three reads; Task 5 owns what happens
with them afterwards.

Also in this task, because they are the same receiver kind and each is a silent-wrong-answer risk on
its own: an instance's `~string`, `~defaultName`, `~objectName` and `~objectName=`, its `~class` and
`~isA`. Measured, `.Object~new~string` is `an Object` and an instance of `K` is `a K`; setting
`~objectName` changes `~string` and `~objectName` and leaves `~defaultName` answering `a K`.

**5b owes only the constructions its own rows make** (D57, and the spec's native-`~new` split):
`Object` and user classes here, `StringTable` in Task 3, `Array` in Task 8, and **the Message object
`~start` answers** in Task 7 -- *not* `.Message~new`, which refuses `93.901` on the oracle and is 5c's.
Twenty-three of the fifty-nine `*__instance.rex` classes refuse a bare `~new` on the oracle and are
5c's; do not build them and do not treat their rows as this phase's business. `Message` is one of the
twenty-three, which is why the two obligations have to be said apart.

**The rooting hazard is this task's, and it needs a targeted witness rather than the subset run.**
`Interp::pool_owner`'s doc comment (`run.rs:3077`) records that a running send's receiver is rooted
only by the `SELF` slot, which a method body may assign over, and names "the task that creates
instances (`~new`)" as the one that can settle it. This task makes it reachable, and it is a
use-after-free rather than a wrong answer.

**Task 1 measured that doc comment false and it is corrected in the tree.** `Interp::message_term`
takes `push_temp(receiver)` before it resolves anything and both engines enter **a program's message
term** through that one function, so a send a program writes has its receiver rooted by the sending
clause's temporaries frame however the body treats `SELF`. That is narrower than "both engines enter
a method body through that one function", which is false: `Interp::send_message` has callers outside
`message_term` -- `required_string_dispatch`, `send_make_string`, `native_new`, `class_factory`,
`native_string`, `native_object_name`, `native_request` and `lib.rs`'s own -- and four of them were
added by Task 1. The window that is real is one of exactly those: the `INIT` send `~new` makes
itself, where the receiver is the new object and `message_term`'s temporary holds the class.
`native_new` takes its own `push_temp` over it, and removing that one reddens the witness.

**The ordinary-send half of that claim is argued, not witnessed, and the fix round measured it.**
Removing `message_term`'s `push_temp(receiver)` (`dispatch.rs`) in a scratch copy leaves
`collect_stress` at 8 passed / 0 failed -- the harshest collector setting this project has -- so
nothing in the tree reddens when that root goes, and the `go`-side `SELF` clobber in
`instance_self_reassigned.rex` contributes nothing to the rooting question. The line stays: absence
of a witness is not evidence it does nothing. What is witnessed is `native_new`'s own `push_temp`,
which `a_method_that_assigns_over_self_keeps_its_exposed_variables` reddens on.

**Two properties the witness program needs, both found by running it.** The instance must not be
held in a caller variable at the moment the mutation is tested -- with `o = .K~new` the caller's slot
roots it and no rooting mutation reddens anything -- so the committed program clobbers `SELF` inside
`INIT` as well. And the exposed value must be wider than `rexx_core::INLINE_BYTES`, or it rides in
the handle, is never a heap object, and the row stays green under every mutation including
`Body::trace` losing the pools.

**The subset-wide stress run cannot see it**, two ways: `collect_stress.rs`'s subset test walks
`SUBSET_FILES`, which contains no gate-table probe, so neither of this task's rows is in it; and no
ordinary program assigns over `SELF`. (Once the task's own witness is in `corpus/phase-5b.txt` the
subset run does read it, so the targeted case and the subset row redden together.) The construct is
legal and reachable -- measured, oracle rc 0, `a kept 192 clobbered`:

```rexx
o = .K~new
say 'a' o~go
::CLASS K
::METHOD init
  expose v
  v = 'kept'
::METHOD go
  expose v
  self = 'clobbered'
  t = ''
  do i = 1 to 100
    t = t || i
  end
  return v length(t) self
```

`collect_stress.rs` already holds targeted cases for exactly this class of hazard; this is one more
beside them.

**Done when**

* both rows agree on both engines under the phase-gate command;
* a program that assigns over `SELF` inside a method body and then allocates enough to force a
  collection agrees on three descriptors, is in `corpus/phase-5b.txt`, and passes under
  `run_program_collect_every_alloc` as a targeted case beside `collect_stress.rs`'s existing ones;
* **`corpus/phase-5b.txt` carries the instance-naming witness.** No gate row sends `~string`,
  `~defaultName`, `~objectName`, `~objectName=`, `~class` or `~isA` to an *instance* -- `creo.rex`
  sends `~type`/`~balance`/`~rate`, `abscla.rex` sends to a class, and Object's instance method row is
  `hasMethod` calls and is 5c's -- so six methods this task calls a silent-wrong-answer risk would
  otherwise have no witness at all. Oracle for the instance receiver, rc 0: `an Object`, then `a K`
  for `~string`/`~defaultName`/`~objectName`, then after `~objectName = 'zed'` both `~string` and
  `~objectName` answer `zed` while `~defaultName` still answers `a K`;
* and **two controls are recorded as run**: dropping `checkAbstract` from the `~new` path makes
  `abscla` construct (the row's own committed control), and not sending `INIT` after the object is
  built reddens `creo`.

**Goal.** `corpus/gate-tables/concepts/objcla.rex` agrees, and both arms of D58 have witnesses.

**Build.** The rule is D58 and the spec carries its evidence: `~define`, `~defineMethods` and

so); `~inherit` and `~uninherit` rebuild the existing behaviour in place (`:1361`, `:1413`, both into

**Make it a property of where the behaviour lives, not a rule restated at each mutator.** A live walk

## Task 3: per-object methods, their scopes, and the restricted-private check

**Goal.** `corpus/gate-tables/concepts/usesem.rex` agrees.

**Measured.** rc 120 today; oracle rc 0, `setmethod one-off` / `not-shared 0` / `enhanced enhanced` /
`still-not-shared 0`. The probe needs `.StringTable~new`, **`StringTable`'s `[]=`** and
`Class~enhanced` as well as `setMethod`. `[]=` exists for **no** receiver kind today -- the native
table has `[]`, `AT`, `PUT` and `UNKNOWN` for `StringTable` and no setter -- and the syntax parses, so
this is a build item rather than a parser one: `a = (7,8,9)` then `a[2] = 5` is rc 120 at
`method "[]=" of class "Array" is not implemented` after printing the `[]` read.

**Build.** `setMethod`, `unsetMethod`, `enhanced`, and the object's own scope. `compile_method_source`
already turns a source string into a method object for `~define` and is what the string and
string-array forms need here.

**It keeps no body, though, and that is the largest single piece of this task.** Its own doc comment
says so -- "The compiled body is validated and not retained" -- so nothing in the tree can *run* a
method compiled from source text, and `usesem`'s `setMethod("EXTRA", "return 'one-off'")` has to run.
Two things follow. A compiled body needs a `(program, directive)` pair, which means filing the parse
as a program of its own. And **a compiled method reports under its own name, not the program's
path**: measured, oracle rc 214, a one-off whose body is `return 1/0` reports `Error 42 running MM
line 1:`, and `parse source` inside one answers `LINUX METHOD MM`. The name is the one the caller
wrote, which `setMethod` upcases and `~define` does not.

**The scope argument is D67 and is the part most easily got silently wrong.** `FLOAT`, the default,
is **one pool per object** shared by all that object's `FLOAT` one-offs and separate from the class's;
`OBJECT` shares the class's. One `FLOAT` method cannot distinguish "one pool per object" from "one
pool per method" -- the spec measures the difference with two.

**The restricted-private check is D66 and has two refusals, not one.** From a program context the
ordinary private check refuses first at dispatch: `97.2 ... cannot accept private message "SETMETHOD"
from this context.` at rc 159, with no method frame on the traceback. `checkRestrictedMethod`
(`ObjectClass.cpp:697`) refuses from a class method of a class the object is not an instance of:
`98.991 Method SETMETHOD may only be invoked from a method of the same object or one of its
classes.` at rc 158, **with** a `Compiled method "SETMETHOD" with scope "Object".` frame. The frame is
the discriminator. `send` and `sendWith` are not in the trio and answer from a program context.

**The per-object first step of the search order is this task's too**, and `usesem.rex` cannot see it:
it defines `EXTRA` only in the object's scope, so an implementation searching the class first and the
object second prints byte-identical output. The spec's discriminating program shadows a class method
of the same name and carries `unsetMethod` with it.

**A one-off `UNINIT` is this task's too**, and it is the silent wrong answer the task's own first
build shipped. `defineInstanceMethod` and `deleteInstanceMethod` each call `checkUninit`
(`ObjectClass.cpp:2314`, `:2338`), so attaching `UNINIT` to one object registers it for finalization
and hiding the name cancels a class's -- measured, oracle rc 0 for both directions, from a forced
collection and at termination alike.

**Done when** `usesem` agrees on both engines; `corpus/phase-5b.txt` carries the precedence program,
the two `FLOAT` methods sharing a pool with a second instance seeing an uninitialised name, and both
restricted-private refusals; and **two controls are recorded as run**: `usesem`'s own committed
control (put a `setMethod` definition in the class's dictionary so it reaches the class's other
instances) reddens `usesem`, and searching the class before the object reddens
the new precedence program while every gate row that agreed before the mutation still agrees after it.
That second control is re-run at Task 10 against the full green table, for the reason Task 2's is.

## Task 5: `UNINIT` (D60, D61, D69), and characterising the sweep order

**Goal.** `corpus/gate-tables/concepts/obdes.rex` agrees, and instance `UNINIT` is delivered.

**Measured, as this task found it.** `obdes.rex` was a silent row: rc 0 and empty stderr on both
sides, oracle stdout `main` / `uninit ran` against a crate stdout of `main`
(`.superpowers/sdd/2026-08-27-phase-5b/task-5-report.md:456`, `:614`). The oracle's half does not
move; the crate's is what this task changes.

**What is already there.** `Heap::collect` returns `CollectStats::pending_uninit`, the unreachable
objects whose flag is set, resurrected rather than swept; `Heap::set_uninit` is the only writer of
`true` and `Heap::clear_uninit_all` is how a caller reports the finalizer ran. `Interp::collect`
(`lib.rs:6446`) carries a `debug_assert!` that the list is empty whose comment names itself as the
site that owes delivery. `ClassGraph::check_uninit` and `parent_has_uninit` are 5a's half of the
propagation -- **but they answer about a class's *instances*, which is deliveries 1 and 2 only.**
Delivery 3 has no predicate at all: the class-object side, where a `::METHOD uninit CLASS` lands,
needs the table the oracle's `requiresUninit` fills. That table is this task's to build, and
`obdes.rex` -- this task's only gate row -- is exactly that side. **Re-measure all of this.**

**Build three deliveries, not one.**

1. **From a collection**, for an instance: replace `Interp::collect`'s assertion with the delivery,
   and `clear_uninit_all` after the finalizer runs. Reproducible shape, five runs of five: `drop` then
   `call gc 'force'`, one instance -- **with allocating clauses between `~new` and the `drop`**, and
   that precondition is not optional. The oracle holds recently allocated objects out of a driven
   collection (`Memory::SaveStackSize`, and `GC('force')` is `collectAndUninit(false)`, which keeps
   that stack), so written without them the witness cannot fire on the oracle at all: measured at
   Task 5 on a program whose padding clauses are bare string assignments, eight give `a c uninit`
   and nine give `a uninit c`. **The threshold is in allocations, not in clauses**, so it does not
   transfer to a program whose clauses allocate more: `corpus/lang/uninit_instance_collected.rex`
   fires with two clauses in that position, and its own comment carries the transcript that says
   which of the two carries it.
2. **At termination, over every live object carrying the flag** -- D69. This is not the same as (1)
   and cannot be built out of it: under D59 a class-scope `EXPOSE` roots an instance for ever, so it
   is never unreachable and a collection-driven delivery never runs its `UNINIT` at all. The oracle
   fires those at termination, measured, and the spec prints the program.
3. **At termination, for class objects** -- D60. Never from a collection, because D59 means a class
   object is never collected.

**Characterise the order, which the spec deliberately does not.** D60 records that the oracle's class
`UNINIT` order at termination is reproducible and is **not** creation order: a three-class program
fires a class declared second after one declared third, three runs of three, and a mixed program
fires runtime-built classes before directive-installed ones. Two witnesses are not a rule. Find the
rule, or establish that it cannot be characterised cheaply and say so; either outcome is the task's
output, and D61 stays in force over class objects until the first one lands.

**ANSWERED at Task 5, from the oracle's source and confirmed by running.** The sweep
(`MemoryObject::lastChanceUninit`, `memory/RexxMemory.cpp:324`) walks `uninitTable`, an
`IdentityTable` at `HashCollection::DefaultTableSize` -- 17 buckets. `HashContents::iterateNext`
(`classes/support/HashContents.cpp:489`) takes buckets in index order and the overflow chain within
one, which `HashContents::put` appends to. The bucket is `getHashValue() % bucketSize`
(`HashContents.hpp:204`), and **`RexxClass::getHashValue` (`classes/ClassClass.cpp:209`) is the hash
of the class's id STRING** -- `h = 31*h + byte` over the bytes (`classes/StringClass.hpp:328`).

So: **`strhash(id) % 17` ascending, ties by the order the classes entered the table.** Nothing about
creation order enters it except as the tie-break.

**Where an entry is made is a separate question, and getting it wrong is silent.** The oracle enters
a class from `RexxClass::checkUninit` (`classes/ClassClass.cpp:1211`), and its callers are the class
factory tail and **`RexxClass::updateSubClasses` (`:1052`)**, which `inherit` (`:1360`) and
`uninherit` (`:1413`) both end in and which recurses into every subclass. The directive
`::CLASS K INHERIT M` is the same path, because `ClassDirective::install` sends `INHERIT` to the
class object (`instructions/ClassDirective.cpp:230`). A first implementation of this task called
`check_uninit` only where a class is *declared*, and four `UNINIT` deliveries went missing at rc 0
with empty stderr -- two class-side and two instance-side, one pair per inherit path. The crate's
`ClassGraph::update_sub_classes` is the single place that closes all four.

**A registered finalizer can still be cancelled, and not by removal.** `RexxObject::uninit`
(`classes/ObjectClass.cpp:2579`) re-checks `hasMethod(UNINIT)` at delivery, and `checkUninit` never
clears anything, so after `.QQ~uninherit(.MX)` the oracle reaches `QQ` in the sweep and runs
nothing: measured, three runs of three, rc 0 with empty stderr, `main / inherited / uninherited /
u MX`. An instance built between an `~inherit` and its `~uninherit` is the same shape and runs no
finalizer either. Confirmed by running, three runs each, rc 0 and
empty stderr: four classes declared `C B A D` fire `D A B C`; twenty declared `A`..`T` fire
`D E F G H I J K L M N O P Q A R B S C T`; three ids colliding in one bucket fire in declaration
order and reverse when the declarations reverse; and a runtime-built class placed at bucket 16 fires
**last**, which falsifies the runtime-before-directive reading above -- that observation was hash
order.

**The same reading is why instances are NOT reproducible**, which is what D61 was protecting:
an instance's `getHashValue` is the inherited `identityHash()`, its address
(`classes/ObjectClass.hpp:335`, `:340`). Measured: one class-side `UNINIT` on a class at bucket 16
beside one live instance answered `instance` before the class 19 times in 20 and after it once.

**So D61 lapses by its own terms over class-against-class order and stays in force over anything
involving an instance.** `corpus/lang/uninit_class_sweep_order.rex` is the committed witness of the
rule; `ClassRegistry::take_uninit_classes_in_sweep_order` is where it is implemented. It predicts the
oracle only while the table has not expanded (`HashCollection::expandContents` doubles and rehashes);
twenty entries do not reach that, measured.

**5a's Task 7 handed three class-`UNINIT` programs to this phase and no task had named them**
(`docs/superpowers/records/2026-08-17-phase-5a/task-7-report.md:333`-`:348`, "All three programs
travel to 5b together"). `obdes.rex` has one class declaring its **own** `UNINIT` and cannot see

::CLASS P / ::METHOD uninit CLASS / ::CLASS K SUBCLASS P

(The mixin arm as 5a handed it over gave `K` a `::METHOD uninit CLASS` of its own. That version

The first is the inherited arm: `K` declares no `UNINIT` and fires one anyway, **before** the parent

## Task 7: `~copy`, `~run`, `~send`/`~sendWith`, `~start`/`~startWith`

**Two of those measurements do not discriminate what the task builds, and a witness written from them

* **`~copy`.** The copy's initial values and `(o == c)` are the same whether the pools were copied or

  `self~run('use arg x; return "ran" x', 'I', 5)` answers `ran 5`, oracle rc 0. Note the D67

**`~run`'s option surface is the largest in this task and nobody has enumerated it.**
`fundclasses.xml` `mthObjectRun`: a Method object, a source string, or an Array of source strings;

measure it before building it.

## Task 8: multidimensional `Array`, and `methodsbyclass` (D63)

**Goal.** `corpus/gate-tables/concepts/methodsbyclass.rex` agrees, with the equivalence arm added.

**Measured.** rc 120 today; oracle rc 0, `element 0` / `dimensions 2` / `methods 1 1` /
`environment Array Directory StringTable`.

**Build.** `.Array~new(2, 3)`, `~dimension`, and `[]`/`[]=` with several indexes. `Body::Array` is a
flat `Vec<Option<ObjRef>>` today, so this is a representation change and not a method addition.

**Add the arm the section states and the probe omits.** `provide.xml` `methodsbyclass` says
`matrix[2, 3] = 0` and `matrix~"[]="(0, 2, 3)` are both valid and equivalent; the committed probe
writes `matrix[2, 3] = 0` once, reads `matrix[2, 3]` once, and never uses the message form. The row's
own committed control already names that half.

**The equivalence arm alone does not make the row see the indexing, and this is the task's real
acceptance problem.** The probe writes one cell and reads the same cell, so **any injective index
mapping passes** -- row-major, column-major, transposed, off by a constant -- because the write and
the read miss together. Adding the message form writes and reads that same cell again: an arity check,
not a mapping check. The committed control catches only the collapse to one subscript. So D63 would
close over an acceptance that cannot see the indexing.

The discriminator is a second, asymmetric cell. Measured, oracle rc 0:

```rexx
m = .array~new(2, 3)
m[1, 2] = 'a12'
m[2, 1] = 'a21'
m~"[]="('b23', 2, 3)
say 'x' m[1, 2] m[2, 1] m[2, 3]      -- x a12 a21 b23
say 'y' m~dimension m~dimension(1) m~dimension(2)   -- y 2 2 3
say 'z' m~size m~items               -- z 6 3
```

`m[1,2]` and `m[2,1]` are distinguishable only under the right mapping, and `~dimension(1)`/
`~dimension(2)` pin the shape where a bare `~dimension` answering `2` would not.

**`oracle_lines` moves with the probe.** `gate_table_c.rs`'s `methodsbyclass` row declares four oracle
lines, checked as `OracleShape::Exactly`, and a structural failure is red in **every** mode -- so an
added output line that leaves the literal alone is red for a reason that has nothing to do with this
task.

**Done when** the row agrees on both engines with the equivalence arm **and the asymmetric second
cell** in the probe, `oracle_lines` matches, and **the control is recorded as run**: the row's
committed control (route `matrix[2, 3] = 0` to a single-index `[]=`) reddens it, and **transposing the
index mapping also reddens it** -- which it cannot do today.
