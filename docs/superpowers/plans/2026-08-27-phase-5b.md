# Phase 5b — an instance exists

**Goal.** Build the mechanisms `docs/superpowers/specs/2026-08-27-phase-5b-instances.md` assigns to
5b, make every gate-table row whose owning phase is `5b` agree with the oracle, land
`corpus/phase-5b.txt`, and flip `5b` into `CLOSED_PHASES`.

**Where this comes from.** That spec, at `01e024157`, after one adversarial review whose six
high-severity findings were verified independently and folded in. Decisions D57-D69 bind. Where a
task below and the spec disagree, the spec wins and the task is wrong.

**Base.** `01e024157`. Corpus 264 of 264; all five gates green at `c7345f7a9`, whose only
descendants are two documentation commits and the spec.

**Delivery order is not free.** Task 1 unblocks every other task: no instance exists until `~new`
does, so nothing after it can be measured before it lands. Tasks 2 to 8 are independent of each
other once Task 1 is in. Task 9 is an audit that wants the rest landed. Task 10 is the flip.

## Global constraints

`docs/superpowers/records/2026-08-17-phase-5a/` carries the constraints this project runs under and
they bind unchanged. The ones this plan leans on hardest:

* **Differential correctness.** stdout, stderr and exit status byte for byte against the oracle, on
  `REXX_ENGINE=ir` **and** `REXX_ENGINE=tree-walker`. Three descriptors read separately, never
  `2>&1`. Probes from a fresh empty directory with absolute paths. The crate bootstraps on every run,
  so bound crate probes with `timeout -s KILL 20`.
* **A silent wrong answer is the worst defect here** and no gate sees one. **Every task below turns a
  loud refusal into an answer**, which is exactly when one is introduced. Probe past the row.
* **The five gate commands** at the end of every task, `--no-fail-fast`, each status read unpiped,
  and **the command that printed a figure quoted beside the figure**.
* **Never run a program listed in `rust/corpus/oracle-crashes.txt`**, and never construct one of
  those shapes.
* Comments: ASCII only, no em-dashes, no historical framing, and no comment states the size of a set.
  `rust/CLAUDE.md`'s comment rule of 2026-08-27 governs: one sentence of overview, the parameters,
  returns and panics, and properties not clear from the implementation. Prefer no comment to a
  paragraph, and assert a load-bearing property in a test instead of describing it.
* Never `git checkout -- <path>` on a file you have edited; `cp` to the scratchpad and restore from
  the copy. Never `rm` with a star glob. Never a bare `git stash`. Commit with `-F`, name paths
  explicitly, never amend.
* **Prefer deleting to rewriting.** Every false sentence the previous two plans shipped arrived as an
  added justification whose argument was right.

**Three rules this phase adds, each because the spec's review found the defect it prevents.**

1. **Treat every "what is already there" paragraph below as a claim to re-measure, not a premise.**
   Four of them were wrong on the previous plan, all in the direction of making the task look
   smaller. Correct the plan file where you find it wrong -- not your brief and not your report.
2. **A witness must be run against a control that makes it fail.** Three probes in this
   neighbourhood were green over mechanisms that were not implemented: gate table D's two `DELEGATE`
   rows, `usesem.rex` for the per-object precedence step, and a replacement `DELEGATE` probe drafted
   during the spec review. Each task below names its control; **record the control as run**, with its
   transcript, or the acceptance is not met.
3. **No check may depend on an ordering the oracle does not reproduce** (D61, D68). Two instance
   `UNINIT`s at termination, and `~completed` sampled before `~result`, are both racy on the oracle,
   measured. If a probe needs two finalizers, force each with `drop` then `call gc 'force'`.

**Measured at `538f35310` by the controller before this plan was written**, and reproduced during the
spec's review at `be1cf430b`: every 5b row of gate table C diverges and every one but `obdes` is
loud; `obdes` is `diverge-stdout` with empty stderr on both sides; both 5b rows of gate table D
`agree` over a mechanism that is not implemented.

## Task 1: `~new`, `INIT`, and the instance seam

**Goal.** `corpus/gate-tables/concepts/creo.rex` and `abscla.rex` agree.

**Measured.** Both are rc 120 today, refused at `method "NEW" of class "Object" is not implemented
(Phase 5)`. Oracle for `creo.rex` is rc 0, `type a savings account` / `balance 1000.00` /
`rate 6.25`; for `abscla.rex` it is rc 158, stdout `declared AB Class`, stderr the `98.989 Class AB
is ABSTRACT and cannot be directly created.` transcript with a `Compiled method "NEW" with scope
"Object".` frame.

**What is already there, probed separately.** `Body::Instance(ScopePools)` exists and is what a class
object's own variables already use; `receiver_kind` (`dispatch.rs:1123`) refuses it with
`Err("an instance of a user class")`, which is the seam. `("Object", "INIT", Arity::Fixed(0),
native_no_op)` is already in the native table. `~objectName`/`~objectName=`/`~string`/`~class`/`~isA`
all answer for a class receiver. **Re-measure all of this.**

**Build.** `RexxClass::completeNewObject` (`ClassClass.cpp:1882`) in its four steps, in order:
`checkAbstract`, set the behaviour from the class's instance behaviour, register `UNINIT` if the
class or a parent defines it, send `INIT` with `~new`'s arguments. The registry already carries the
`UNINIT` flags (`has_uninit`, `parent_has_uninit`) that step three reads; Task 5 owns what happens
with them afterwards.

Also in this task, because they are the same receiver kind and each is a silent-wrong-answer risk on
its own: an instance's `~string`, `~defaultName`, `~objectName` and `~objectName=`, its `~class` and
`~isA`. Measured, `.Object~new~string` is `an Object` and an instance of `K` is `a K`; setting
`~objectName` changes `~string` and `~objectName` and leaves `~defaultName` answering `a K`.

**5b owes only the constructions its own rows make** (D57, and the spec's native-`~new` split):
`Object` and user classes here, `StringTable` in Task 3, `Array` in Task 8, `Message` in Task 7.
Twenty-three of the fifty-nine `*__instance.rex` classes refuse a bare `~new` on the oracle and are
5c's; do not build them and do not treat their rows as this phase's business.

**The rooting hazard is this task's, and it is named in the tree.**
`Interp::pool_owner`'s doc comment (`run.rs:3077`) records that a running send's receiver is rooted
only by the `SELF` slot, which a method body may assign over, and names "the task that creates
instances (`~new`)" as the one that can settle it. Nothing can reach it today because no `::METHOD`
body runs with a non-class receiver. This task makes it reachable, and it is a use-after-free rather
than a wrong answer. The instrument is `run_program_collect_every_alloc`, which collects on every
allocation; a watermark run cannot see a missed root.

**Done when** both rows agree on both engines, the collect-on-every-allocation stress mode passes
over the new corpus programs, and **two controls are recorded as run**: dropping `checkAbstract` from
the `~new` path makes `abscla` construct (the row's own committed control), and not sending `INIT`
after the object is built reddens `creo`.

## Task 2: the behaviour snapshot (D58)

**Goal.** `corpus/gate-tables/concepts/objcla.rex` agrees, and both arms of D58 have witnesses.

**Measured.** `objcla.rex` is rc 120 today; oracle rc 0, `before 0` / `after 0` / `fresh 1`.

**Build.** The rule is D58 and the spec carries its evidence: `~define`, `~defineMethods` and
`~delete` replace the class's instance behaviour with a copy so existing instances keep the old one
(`ClassClass.cpp:860`-`:862`, `:531`-`:533`, `:962`-`:964`, each with the C++'s own comment saying
so); `~inherit` and `~uninherit` rebuild the existing behaviour in place (`:1361`, `:1413`, both into
`updateSubClasses` at `:1036`), so existing instances see the change.

**Make it a property of where the behaviour lives, not a rule restated at each mutator.** A live walk
of the class graph on every send gets `~inherit` right and `~define` wrong; a copy on both families
gets `~define` right and `~inherit` wrong. Both are rc 0 with empty stderr.

**Done when** `objcla` agrees on both engines; `corpus/phase-5b.txt` carries the `~inherit` and
`~uninherit` witnesses (the spec prints both, and neither exists in the corpus today -- no committed
`.rex` combines `~inherit` with `~new`); and **two controls are recorded as run**: `objcla`'s own
committed control (rebuild the lookup from the class on every send) reddens `objcla`, and copying the
behaviour on `~inherit` too reddens the new `~inherit` witness while leaving every gate row green.
The second control is the point of the task: it is the mutation no existing row can see.

## Task 3: per-object methods, their scopes, and the restricted-private check

**Goal.** `corpus/gate-tables/concepts/usesem.rex` agrees.

**Measured.** rc 120 today; oracle rc 0, `setmethod one-off` / `not-shared 0` / `enhanced enhanced` /
`still-not-shared 0`. The probe needs `.StringTable~new` and `Class~enhanced` as well as
`setMethod`.

**Build.** `setMethod`, `unsetMethod`, `enhanced`, and the object's own scope. `compile_method_source`
already turns a source string into a method object for `~define` and is what the string and
string-array forms need here.

**The scope argument is D67 and is the part most easily got silently wrong.** `FLOAT`, the default,
is **one pool per object** shared by all that object's `FLOAT` one-offs and separate from the class's;
`OBJECT` shares the class's. One `FLOAT` method cannot distinguish "one pool per object" from "one
pool per method" -- the spec measures the difference with two.

**The restricted-private check is D66 and has two refusals, not one.** From a program context the
ordinary private check refuses first at dispatch: `97.2 ... cannot accept private message "SETMETHOD"
from this context.` at rc 159, with no method frame on the traceback. `checkRestrictedMethod`
(`ObjectClass.cpp:697`) refuses from a class method of a class the object is not an instance of:
`98.991 Method SETMETHOD may only be invoked from a method of the same object or one of its
classes.` at rc 158, **with** a `Compiled method "SETMETHOD" with scope "Object".` frame. The frame is
the discriminator. `send` and `sendWith` are not in the trio and answer from a program context.

**The per-object first step of the search order is this task's too**, and `usesem.rex` cannot see it:
it defines `EXTRA` only in the object's scope, so an implementation searching the class first and the
object second prints byte-identical output. The spec's discriminating program shadows a class method
of the same name and carries `unsetMethod` with it.

**Done when** `usesem` agrees on both engines; `corpus/phase-5b.txt` carries the precedence program,
the two `FLOAT` methods sharing a pool with a second instance seeing an uninitialised name, and both
restricted-private refusals; and **two controls are recorded as run**: `usesem`'s own committed
control (put a `setMethod` definition in the class's dictionary so it reaches the class's other
instances) reddens `usesem`, and searching the class before the object leaves every gate row green
while reddening the new precedence program.

## Task 4: `FORWARD` and `DELEGATE` (D62)

**Goal.** Gate table D's two 5b rows agree over probes that exercise the mechanism.

**Measured.** Both rows `agree` today and neither sends the delegated message: each probe is
`say 'main'` plus directives, so both sides print `main` at rc 0 whether or not `DELEGATE` exists.

**Build.** `FORWARD` as an instruction, then `DELEGATE` as the equivalence `dire.xml` states it as --
`expose delegateName` plus `forward to(delegateName)`, and for `::ATTRIBUTE` the pair `name` and
`name=`. Measured, a plain `forward class (super)` returns from the forwarding method rather than
continuing it.

**Replace both probes, under two constraints the spec measured.** `gate_table_d.rs`'s
`expected_oracle_lines` bounds a non-refusing row's oracle stdout at exactly one line, so a two-line
probe reports `unanswered` and can never reach `agree`. And the `::ATTRIBUTE` probe must send the
setter as well as the getter, reading back **through the delegate object** -- the spec prints both
one-line probes.

**Done when** both rows agree on both engines with the replaced probes, and **the control is recorded
as run**: replacing `::attribute at delegate d` with a plain `::attribute at` in the setter probe
makes it print `main AT` instead of `main via-set`. That control is not optional bookkeeping. A draft
of the same probe read `k~at` instead of `k~peek~at` and passed with `DELEGATE` unimplemented; the
control is what separated them.

## Task 5: `UNINIT` (D60, D61, D69), and characterising the sweep order

**Goal.** `corpus/gate-tables/concepts/obdes.rex` agrees, and instance `UNINIT` is delivered.

**Measured.** `obdes.rex` is the phase's only silent row: rc 0 and empty stderr on both sides, oracle
stdout `main` / `uninit ran`, crate stdout `main`.

**What is already there.** `Heap::collect` returns `CollectStats::pending_uninit`, the unreachable
objects whose flag is set, resurrected rather than swept; `Heap::set_uninit` is the only writer of
`true` and `Heap::clear_uninit` is how a caller reports the finalizer ran. `Interp::collect`
(`lib.rs:6446`) carries a `debug_assert!` that the list is empty whose comment names itself as the
site that owes delivery. `ClassGraph::check_uninit` and `parent_has_uninit` are 5a's half of the
propagation. **Re-measure all of this.**

**Build three deliveries, not one.**

1. **From a collection**, for an instance: replace `Interp::collect`'s assertion with the delivery,
   and `clear_uninit` after the finalizer runs. Reproducible shape, five runs of five: `drop` then
   `call gc 'force'`, one instance.
2. **At termination, over every live object carrying the flag** -- D69. This is not the same as (1)
   and cannot be built out of it: under D59 a class-scope `EXPOSE` roots an instance for ever, so it
   is never unreachable and a collection-driven delivery never runs its `UNINIT` at all. The oracle
   fires those at termination, measured, and the spec prints the program.
3. **At termination, for class objects** -- D60. Never from a collection, because D59 means a class
   object is never collected.

**Characterise the order, which the spec deliberately does not.** D60 records that the oracle's class
`UNINIT` order at termination is reproducible and is **not** creation order: a three-class program
fires a class declared second after one declared third, three runs of three, and a mixed program
fires runtime-built classes before directive-installed ones. Two witnesses are not a rule. Find the
rule, or establish that it cannot be characterised cheaply and say so; either outcome is the task's
output, and D61 stays in force over class objects until the first one lands.

**Done when** `obdes` agrees on both engines; `corpus/phase-5b.txt` carries a one-instance collection
delivery and a one-instance termination delivery; the order question has an answer recorded either
way; `gate_table_c.rs`'s `obdes` control text is corrected from "stop running `UNINIT` before the
object's storage is reclaimed" to "skip the termination sweep", since under D59 a class object's
storage is never reclaimed; and **the control is recorded as run**: skipping the termination sweep
reddens `obdes`, silently, at rc 0 with empty stderr on both sides.

## Task 6: the licensed divergences (D59a)

**Goal.** D59's licence has witnesses the harness runs.

**Build.** A numbered DEVIATION in the shape `docs/superpowers/plans/phase-4-exclusions.txt` already
uses -- IMPLEMENTED / SCOPE / WHY, with pinned witnesses -- which the parent spec's D41 already cites
for `~identityHash`. **Not a prose `.txt` nobody executes**: a criterion satisfied by committing a
file with any content is satisfied by a file that has rotted.

The licence covers four consequences and this task owns the one 5b makes reachable: a class's
`UNINIT` running in the termination sweep rather than at a driven collection. The witness runs both
interpreters and **asserts the expected divergence**, so it reddens if the crate ever starts matching
or starts diverging differently.

The other three are recorded with the phase that owes them: `~subclasses` keeping a dropped class and

asymmetry is stated in D59a with its measurement (100,000 `~subclass` calls, oracle rc 0
`done 100001`, crate rc 137 OOM-killed at the 1G cap) and needs no runnable witness, because a
witness that OOM-kills a gate run is worse than the prose.

**Done when** the DEVIATION exists, the harness runs its witness, and **the control is recorded as
run**: making the crate match the oracle on that program reddens the DEVIATION's assertion.

## Task 7: `~copy`, `~run`, `~send`/`~sendWith`, `~start`/`~startWith`

**Goal.** Each has a witness in `corpus/phase-5b.txt` and agrees.

**Measured, oracle, all rc 0 unless noted.** `~copy` is shallow, copies the object's own scope and
its exposed variables, and `(o == c)` is `0`. `o~send('M', 3)` and `o~sendWith('M', .Array~of(4))`
answer from a program context. `o~run(...)` is `97.2` at rc 159 from a program context -- Task 3's
check, reached again here. `o~start('M', 5)` answers a `Message`; `m~result` is the value and
`m~completed` after it is `1`.

**Build.** The four paths, plus enough of `Message` for `~result`, `~completed` and `~hasError`.
`send` and `sendWith` also accept an array whose first item is the name and whose second is a class to
start the method search from -- the dynamic form of the `~m:scope` override 5a built statically. That
is documented in `mthObjectSend`/`mthObjectSendWith` and was **not** measured while writing the spec;
measure it before building it.

**D68 bounds what may be asserted.** `~start`'s interleaving with the program that started it is not
reproducible (twenty runs, two orders), and **`~completed` sampled before `~result` is part of that
interleaving** -- forty runs split thirty to ten. A corpus program may assert `~result`'s value and
`~completed` after it, and nothing else about timing.

**Done when** each of the four has a witness that agrees on both engines, and **the control is
recorded as run**: making `~copy` share the receiver's scope pools instead of copying them reddens the
`~copy` witness at rc 0.

## Task 9: the instance-side reading of 5a's limits

**Goal.** Every limit 5a pinned with a class as the receiver is re-measured with an instance.

**Where this comes from.** The parent spec calls it Task 7's recorded debt and 5b's mechanism set
carries it as a row. It is an audit, not a build: 5a could only send messages to class objects, so
every refusal text, error number and traceback line it pinned was measured on one receiver kind and
assumed for the other. A limit measured on one and assumed for the other is a claim, not a
measurement.

**Method.** Walk 5a's landed error and refusal sites, and for each, send the same message to an
instance. The differences to expect are in the receiver's rendering (`an Object`, `a K`) and in the
`Compiled method "X" with scope "Y".` frame. Anything that diverges is either a defect this task
fixes or a row `corpus/phase-5b.txt` gains.

**Done when** the walk is complete and recorded, every divergence it found is closed or has a named
owner, and the report says which sites were checked -- **not** "all of them", which is the shape this
project has shipped wrong repeatedly. Name the enumeration the walk was derived from and commit it.

## Task 10: the flip

**Goal.** `5b` gates.

**Build.** `CLOSED_PHASES` in `rust/crates/rexx-exec/tests/gate_tables/mod.rs` gains `"5b"`.

**Done when** D65's criteria are met at one commit: every `5b` row in both tables `agree` with no
structural failure; every program in `corpus/phase-5b.txt` agrees on three descriptors on both
engines; Task 6's DEVIATION runs; `CLOSED_PHASES` holds `"5b"`; and the five gates pass with the
command that printed each figure quoted beside the figure.

**Re-run the eight axes** against `bench-baselines/pinned/rexx-run-15a1ffa98` and record the result,
interleaved rather than as two suite runs. `~new` puts an allocation and a message send on paths that
had neither, so a regression here is invisible unless it is looked for and the figure belongs in the
record whichever way it goes.

**And 5b turns three parked bench programs live, which is a second obligation and not the same one.**
`bench-programs/dispatch.rex`, `alloc.rex` and `heapshape.rex` all exit 120 on this crate today and
all need `~new`; `dispatch` and `alloc` are in `rexx-bench`'s benchmarked list already, and
`heapshape` is in `NOT_BENCHMARKED` because it reports its own timing. `crates/rexx-bench/src/lib.rs`
says so in its own test's doc comment, which names Phase 5 as when `heapshape` starts running.
Two consequences:

* **A program that starts running cannot show a regression against a baseline in which it did not
  run.** Its first crate figure is a new baseline row, not a comparison, and must be recorded as one.
  Saying "no regression on eleven axes" when three of them have no prior figure is the shape this
  project calls a ratio flattered by its denominator.
* **`dispatchclass.rex` and `alloc4c.rex` were written as stand-ins and say so.** `dispatchclass`'s
  header says it "does not replace dispatch.rex or relieve whichever task unblocks it";
  `alloc4c`'s says it "is not a substitute for a collection-forcing measurement once message sends
  land". This is that task. Decide, and record, whether each stand-in stays an axis beside the
  program it stood in for or is retired -- **do not leave both in the suite unexamined**, which
  double-counts a dimension in every later comparison.
