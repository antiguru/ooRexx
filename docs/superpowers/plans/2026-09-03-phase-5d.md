## The premise, in one paragraph

Gate table C's method rows are `hasMethod` readbacks, so a hollow class scores full marks: **192 of
308 sampled documented methods have no body and every one of those rows is green.** Meanwhile the 110

`gate_table_c.rs:1548`'s `every_closed_phase_this_table_owns_rows_for_is_gated` makes a committed

## Task 2 — the method-body table (D76)

**The instrument the rest of the object model has been missing.** Table C asks `hasMethod`; this asks
whether the method *works*.

**The sweep.** For every row of `class-methods.txt`, send the documented name to a real receiver —
the instance arm to `class-set.txt`'s construction expression, the class arm to the class object —
and classify:

* **`answers`** — reached a body and agreed with the oracle;
* **`loud`** — refused at rc 120 naming the method;
* **`diverge`** — answered and disagreed with the oracle.

**The gate is one rule: no row may move `loud` → `diverge`.** `loud` → `answers` is progress and is
not gated. A count of implemented bodies is **not** a criterion.

**Shown to fail:** make one `loud` row answer something the oracle does not, confirm the gate
reddens, revert.

**The measured shape to start from**, 2026-09-03, instance arm, one program each, no arguments:

| class | rows | `loud` | reached a body |
|---|---|---|---|
| `String` | 118 | 80 | 38 |
| `Array` | 44 | 27 | 17 |
| `Directory` | 31 | 18 | 13 |
| `MutableBuffer` | 51 | 49 | 2 |
| `Method` | 17 | 14 | 3 |
| `TimeSpan` | 47 | 4 | 43 |

`TimeSpan` is high because its bodies are Rexx in `CoreClasses.orx`.

**The zero-argument send classifies `loud` exactly, and that is measured, not assumed.** The refusal
fires **before** any argument handling: `'abcdef'~substr` with no arguments is rc 120
`method "SUBSTR" of class "String" is not implemented`, while an implemented method sent at the wrong
arity raises an ordinary error containing no such text — `.Array~of(1,2)~at` is rc 163
`Compiled method "AT" with scope "Array"`. **So no signature source is needed to find the `loud`
rows**, and an arity error can never be misfiled as `loud`.

**Two passes.** Pass one is crate-only over every row and produces the `loud` set. Pass two runs the
oracle **only over the rows that are not `loud`**, sending both sides the same arguments — which
needs no signature source either. On the sample's ratio, roughly a third of the rows reach the
oracle.

**What that trade costs**, and it should be stated in the report rather than discovered later: a
method needing arguments is compared on the same wrong ones, so `answers` is a weaker claim than the
table could carry. The gated rule does not rest on it. **A stale table asserting `loud` over a row
that now diverges is worse than no table**, so the refresh path is part of the deliverable.

**Also in this task: D73's guard**, owed since 5c's spec made it a criterion and never built. For
every class `class-set.txt` marks `unreachable`, a committed test that its documented construction
route still refuses, on both engines, oracle answer recorded beside it, derived from the status
column rather than a list of names — and **shown to fail** by making one constructible.

## Task 3 — operator methods on instances

**Measured blocker:** ``the operator `+` applied to an instance of a user class is not implemented
(Phase 5)``, from `.DateTime~new + .TimeSpan~fromSeconds(5)`, where `DateTime` defines `::METHOD "+"`
in the bootstrap and the oracle answers `DateTime` at rc 0.

**One mechanism, and it is under a lot**: `Comparable`, `Orderable`, every `TimeSpan` and `DateTime`
arithmetic path, and any user class defining an operator. Start from `operator_operand_gap` and its
call sites.

**Scope every operator the reference documents as overridable**, not just `+`. Comparison operators
have their own subtlety — the oracle's default for `=` on two instances is identity, and a class
defining `"="` changes what `sort` and `Comparable` do — so measure the default *before* changing it
and keep a witness for the unoverridden case.

**Witness:** a corpus program covering a user-defined `"+"`, a bootstrap arithmetic path, and the
refusal that must remain when no operator method is defined. **Shown to fail at BASE.**

**Read the benchmark axes after this one.** Operator dispatch is on the hottest path in the
interpreter, and per-step thresholds hid a +32.58% cumulative drift once. State the figure whether or
not it moved.

**D77: this task does not touch `Alarm` or `Ticker`.** It will move both *closer* to constructing.
That is not progress against a row count and the report should not present it as any.

## Task 4 — `::REQUIRES` of a program file

**Measured:** `::requires 'lib.rex'` is rc 120 `::REQUIRES is not implemented (Phase 5)` here against
an oracle rc 0 that makes the required file's public routine **and** public class both reachable.

**What it needs**, and the order to build it in: the four-route search — cwd, the program's own
directory, `REXX_PATH`, `PATH` — plus extension appending; parsing and installing the required file's
public directives into the requiring package; running its prologue **once** however many times it is
required; and detecting circular requires.

**A narrowed search turns an honest refusal into a loud wrong answer**, which is the worst outcome
available here. Measure each of the four routes against the oracle separately rather than
implementing the first and assuming the rest.

**`::REQUIRES LIBRARY` is not this task's** — it needs a native library loader and Task 1 re-owned it
to Phase 7. Confirm your change leaves it refusing exactly as before.

**Witness:** a corpus program with a required file beside it. Note that this is the first corpus
program needing a second file; check how the runner stages a program's directory before designing it.
