# Phase 9b: RexxUtil, implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to
> implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the RexxUtil routines and the other sites spec section 4 gives Phase 9, so every
9b gate group passes under the suite harness apart from rows the exclusion test accepts, after first
clearing the 9a carry-in that the Phase 9 budget depends on.

**Architecture:** Task 1 settles the budget instrument and removes 9a's native-call regression. Task 2
commits the 9b gate-group file and the durable perf pin. Tasks 3 to 8 implement the routines in
batches of one family each (stems, files, file tree, messages, process and session, semaphores),
each routine witnessed by its ooTest group or by a corpus program checked against the oracle. Task 9
takes the package and library sites. Task 10 closes 9b.

**Tech Stack:** Rust; `rexx-exec` (`src/builtin/rexxutil.rs`, `src/internal_routines.rs`, tests).
No new dependency.

**Spec:** `docs/superpowers/specs/2026-10-10-phase-9-core-conformance.md`, section 4 (9b's scope),
section 2 (D1 judgement and row files), section 8 (performance), section 9 (sub-phases and check
levels). Carry-in: `.superpowers/sdd/queued/2026-10-13-phase-9b-carry-in.md`. Baseline:
`docs/superpowers/plans/phase-9a-gate.md` and `docs/superpowers/records/2026-10-11-phase-9a/suite-close/`.
Oracle sources: `interpreter/platform/unix/SysRexxUtil.cpp`, `interpreter/runtime/RexxUtilCommon.cpp`.

## Global Constraints

* **Specialization is internal** (`rust/CLAUDE.md`, Moritz 2026-10-13): no refusal of the form
  "this crate does not keep X" and no new side map keyed by an id; if a routine seems to need one,
  stop and report it (Phase 9b1 owns the object model).
* **Behaviour.** The corpus differential stays identical except where a task names the programs it
  changes; each is witnessed against the oracle. New corpus witnesses go in `rust/corpus/phase-9.txt`;
  a new `corpus/lang/*.rex` needs its `crates/rexx-parse/tests/sourceline_oracle/<name>.txt`
  generated by that test's oracle driver.
* **`unsafe`**: no new site (`crates/rexx-core/tests/unsafe_sites.rs`). A routine that cannot be
  written without one (`SysFork` is the likely case) is reported to Moritz with the safe alternative
  measured, not written. No new dependency.
* **Oracle runs**: `( ulimit -v 1048576; LD_LIBRARY_PATH=/home/moritz/dev/repos/ooRexx/build/lib
  timeout -k 5 20 /home/moritz/dev/repos/ooRexx/build/bin/rexx FILE )` from a fresh empty directory
  you `mkdir`; stdout, stderr and status compared separately; `rust/corpus/oracle-crashes.txt` read
  first. Every crate interpreter run under `memcap 2G` and `timeout`, every test binary and build under
  `memcap 8G`, `-j 4`, `CARGO_INCREMENTAL=0`.
* **Read-only**: the C++ tree, `samples/`, `build/`, `ootest/`, `oodocs/`, `testbinaries/`, `api/`.
* **Prose**: comments and docs state decisions, never a mechanism that does not exist yet, never a
  set's size, no em-dashes and no ` -- `; a false sentence is deleted. Extent claims carry the command
  that derived them. Every witness's stdout is read to confirm each path it claims prints.
* **Shell**: no `bash -c`/`sh -c` wrappers; `rm` only with literal absolute paths, no globs; never
  `git checkout`/`stash`/`reset`; mutants are reversed by an exact edit and confirmed with
  `git diff --stat`.
* **Foreground checks.** Every check runs in the foreground with a bound under 10 minutes. Never end
  a turn waiting on a background command or a monitor: nothing wakes an agent that does.
* **Per-task check, at most 5 minutes where possible:** `cargo fmt --all --check`, `cargo clippy -p
  <touched crates> --all-targets -- -D warnings`, the test binaries covering what changed, every test
  binary the change can affect (`phase_ten_reasons`, `closed_phases`, `owners`, the refusal tables,
  `collect_stress` for anything that allocates), and the task's ooTest groups through the suite harness
  (`REXX_SUITE_GATE=1 REXX_SUITE_GROUPS=<dir/group,...> cargo test --release -p rexx-exec --test suite`).
  Commands and exit statuses in the report, unpiped.
* **Refusal tables**: deleting or relabelling a `Loud` site re-derives `rust/corpus/refusal-sites.tsv`
  (`REXX_REFUSAL_SITES_REFRESH=1 cargo test -p rexx-exec --test refusal_sites`) and keeps
  `refusal-dispositions.tsv`, `closed_phases` and `owners` green in the same commit.
* **Derived rows.** A task that unblocks tests re-derives every derived row that records them, in the
  same commit: `concurrency_tests`' whole-group rows (`REXX_WHOLE_GROUPS_ONLY`), `rust/corpus/sim-gate.tsv`,
  and the suite rows. 9a's close failed three times on rows left stale by unblocking.
* **Budget instrument** (Moritz 2026-10-13): callgrind whole-process instructions, libc and ld
  included, against the pin. A task that touches dispatch, allocation, native calls or a per-call path
  measures against the pin with `rust/bench-programs/callgrind.sh` and reads the whole-process column
  before reporting; no program over +0.5%.
* **Durable artifacts**: `/tmp` is wiped on reboot. Anything a later step reads (the pin, run outputs
  a record cites) lives outside `/tmp`: the pin at `/home/moritz/dev/repos/ooRexx-p9-pin/`, run
  outputs copied into `docs/superpowers/records/`.
* **Mechanical batches.** A routine with one obvious oracle answer is one function and one witness.
  An item that turns out to need a new store, a new identity rule, a change of a shared path or a
  daemon is reported and moved by the controller, not widened inside the batch. A routine that needs
  the daemon keeps its Phase 10 label with the `Rxapi` reason (spec section 4).

## Rulings made in this plan

* Ruling: the carry-in comes first (Task 1) because Task 3 onward measure against the pin with the
  whole-process instrument, which `callgrind.sh` does not yet report -- the carry-in file's item 2 is
  ruled by Moritz -- if wrong, Task 1 moves after Task 8.
* Ruling: the routines are batched by family (stems, files, tree, messages, process and session,
  semaphores) because each family shares its argument helpers and its oracle file region in
  `SysRexxUtil.cpp` -- a reviewer can reject one family while approving another -- if wrong, a family
  splits into per-routine tasks.
* Ruling: `TEST_SLEEP_DURATION`'s simulation-clock run stays with 9d (carry-in, Moritz 2026-10-13),
  even though `SysSleep` is a RexxUtil routine -- it is a harness change, not a routine -- if wrong, it
  joins Task 7.

## Review Focus

1. **Stems that are not plain arrays.** A stem with a default value, a non-numeric `stem.0`, missing
   tails below `stem.0`, or tails that are not whole numbers, passed to `SysStemSort`, `SysStemCopy`,
   `SysStemDelete` or `SysStemInsert`. The oracle's answer (error number or rc) is the expected one.
   Task 3 pins each shape in its witness.
2. **Paths that are not simple.** Names with spaces, non-ASCII bytes, a trailing slash, a symlink to a
   directory, a dangling symlink, and a directory without read permission, through the file routines and
   `SysFileTree`. Task 4 and Task 5 each pin the shapes that apply to them.
3. **An oracle crash inside RexxUtil.** `SysStemSort` has a known one-line oracle crash (upstream
   SF #2068, project memory). Task 3 reads `oracle-crashes.txt` and records the shape there if it is not
   listed, and the crate's answer for that shape is pinned by a crate-only test with its reason.
4. **Concurrency.** `SysWait`, `SysFork`, `SysCreatePipe` and the named semaphores used from two
   activities at once. Task 7 and Task 8 run each witness under the scheduler's simulation mode as well
   as normally (`concurrency_tests`' S2 list where it applies).
5. **Time zones and clocks.** `SysGetFileDateTime` and `SysSetFileDateTime` round-trip under a non-UTC
   `TZ`, and across a daylight-saving boundary. Task 4 runs its witness with `TZ=Europe/Zurich` on both
   sides.
