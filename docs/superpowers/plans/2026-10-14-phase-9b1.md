# Phase 9b1: a uniform object model, implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to
> implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** No representation of a value is observable from a Rexx program. String and the numbers
are value-based. Packages, programs, executables and messages are objects the collector frees. Every
per-object side map is a field of its object, pruned with it, or compiled data freed with its program.

**Architecture:**
- Task 1 states the value-based rule (Deviations, the `objectName=` refusal, a witness of what stays
  specified). It also adds the refusal-text test that tracks the leaks still open.
- Tasks 2 and 3 fix the small defects the rule does not license.
- Tasks 4 and 5 turn the Package into a heap object, first holding its state and then collected.
- Task 6 gives programs a lifetime.
- Task 7 collects executables and messages and charges their weight to the trigger.
- Task 8 sweeps the remaining side maps.
- Task 9 closes 9b1.

**Tech Stack:** Rust. `rexx-core` (heap, bodies, collector), `rexx-exec` (`lib.rs` `Interp`,
`install.rs`, `environment.rs`, `dispatch/`), `rexx-parse` (`Program`). No new dependency unless a
task reports why and the controller rules on it.

**Spec:** `docs/superpowers/specs/2026-10-14-phase-9b1-uniform-object-model.md`. Inputs:
`.superpowers/sdd/2026-10-14-phase-9b1/scout-leaks.md` (leaks L1-L12 with probes and code sites, and
the side maps grouped by object), `scout-deviations.md` (Deviation classes and the identity probes),
and `spec-review.md`. Baseline: `docs/superpowers/plans/phase-9b-gate.md` ("9b close") and
`docs/superpowers/records/2026-10-13-phase-9b/close2/`.

## Global Constraints

* **Specialization is internal** (`rust/CLAUDE.md`): no new refusal of the form "this crate does not
  keep X", and no new side map keyed by a numeric id. Spec section 5's three states are the only
  allowed homes for per-object state.
* **Value-based** (spec section 1): plain `.String` values, which includes the numbers, `.true` and
  `.false`, carry no per-object state. Subclass and enhanced strings keep full identity.
* **Behaviour.** The corpus differential stays identical except where a task names the programs it
  changes. Each changed program is witnessed against the oracle. New witnesses go in
  `rust/corpus/phase-9.txt`. A new `corpus/lang/*.rex` needs its
  `crates/rexx-parse/tests/sourceline_oracle/<name>.txt`, generated by that test's oracle driver.
* **`unsafe`**: no new site (`crates/rexx-core/tests/unsafe_sites.rs`).
* **Oracle runs**: `( ulimit -v 1048576; LD_LIBRARY_PATH=/home/moritz/dev/repos/ooRexx/build/lib
  timeout -k 5 20 /home/moritz/dev/repos/ooRexx/build/bin/rexx FILE )`, from a fresh empty directory
  you `mkdir`. Compare stdout, stderr and status separately. Read `rust/corpus/oracle-crashes.txt`
  first. Run every crate interpreter under `memcap 2G` and `timeout`, and every test binary and build
  under `memcap 8G`, `-j 4`, `CARGO_INCREMENTAL=0`.
* **Read-only**: the C++ tree, `samples/`, `build/`, `ootest/`, `oodocs/`, `testbinaries/`, `api/`.
* **Prose**: comments and docs state decisions, never a mechanism that does not exist yet, and never
  a set's size. No em-dashes, no ` -- `, no structuring semicolons. A false sentence is deleted.
  Extent claims carry the command that derived them. Read every witness's stdout to confirm that each
  path it claims actually prints.
* **Shell**: no `bash -c`/`sh -c` wrappers. `rm` only with literal absolute paths, no globs. Never
  `git checkout`/`stash`/`reset`. Reverse a mutant by an exact edit and confirm with
  `git diff --stat`. Never `git push`.
* **Foreground checks.** Every check runs in the foreground with a bound under 10 minutes. Never end a
  turn waiting on a background command or a monitor: nothing wakes an agent that does.
* **Per-task check, at most 5 minutes where possible:**
  - `cargo fmt --all --check`;
  - `cargo clippy -p <touched crates> --all-targets -- -D warnings`;
  - the test binaries covering what changed;
  - `collect_stress` for anything that allocates or roots;
  - the refusal tables, `owners`, `closed_phases` and `phase_ten_reasons`;
  - the gated release corpus;
  - the task's ooTest groups through the suite harness (the command is in
    `docs/superpowers/plans/phase-9b-gate.md`).

  Record commands and exit statuses in the report, unpiped.
* **Refusal tables**: deleting or relabelling a `Loud` site re-derives `rust/corpus/refusal-sites.tsv`
  (`REXX_REFUSAL_SITES_REFRESH=1 cargo test -p rexx-exec --test refusal_sites`), in the same commit.
* **GC rooting.** Every new value held across an allocation is rooted the way the surrounding code
  roots it. Every new root gets a test that goes red with the root deleted (9b escaped two of these).
* **Budget instrument** (Moritz 2026-10-13): callgrind whole-process instructions, libc and ld
  included, against the pin `/home/moritz/dev/repos/ooRexx-p9-pin/rexx-run`, with
  `rust/bench-programs/callgrind.sh -B 0.5`. A task that touches the send, call, package-entry,
  allocation or collector paths measures fibcall, fibfunc, extcall, dispatch, dispatchclass, sendloop,
  varlookup, pkglocal, startup, alloc and hashnew at the task. Read the whole-process column. No

* **Durable artifacts**: `/tmp` is wiped on reboot. Anything a record cites lives outside `/tmp`.
* **Shared paths.** An item that turns out to need a change outside its task's files, a new identity
  rule or a new store is reported, and the controller moves it. It is not widened inside the task.

## Rulings made in this plan

* Ruling: the Package object (Tasks 4, 5) comes before program lifetime (Task 6) -- `Method~new` and
  `Package~new` programs are reachable through their package object, so no program can be freed while
  packages are global roots -- if wrong, Task 6 moves first and frees only package-less programs.
* Ruling: Package state moves into the object (Task 4) before the object is collected (Task 5) -- a
  reviewer can judge the state move by behaviour alone (copy, REXX package copy), and collection by
  `TESTRECLAIM01` and memory -- if wrong, they merge.
* Ruling: the refusal-text test (spec criterion 2) lands in Task 1 with an allow-list of today's
  sites, each tagged with the task that removes it. Each task shrinks the list, and Task 9 checks it
  holds only the final survivors -- a test that is red until the phase ends cannot gate a task -- if
  wrong, the test lands at Task 9.

## Review Focus

1. **A package collected while still in use.** A package whose only reference is a running
   activation, a `.context~package` held in a variable, a class or routine defined in it, or another
   activity's frame. Expected: it is never collected while any of these reaches it. Task 5 pins each
   shape under `collect_stress`, and runs one from two activities under the scheduler's simulation
   mode.
2. **Re-requiring after collection.** `::requires 'x.cls'`, drop every reference, collect, then
   require it again. Expected: it loads again, and the oracle's prolog-run count and class identity
   answers hold (measure the oracle first). Task 5 pins it.
3. **A copied package mutated.** `p2 = p~copy` then `p2~addRoutine`, `p2~addClass` and
   `p2~setSecurityManager`. Expected: `p` is unchanged, `p2` changed, as on the oracle. Task 4 pins
   it, including a copy of the REXX package.
4. **A stale program id.** An activation, plan cache entry or Method object whose program was freed,
   for example a Method created in a loop and dropped, while a frame from it is still on a stack
   (`.context~stackFrames` held in a variable). Expected: never a wrong program, never a panic. Task 6
   pins it with a test that reuses freed slots under `collect_stress`.
5. **Value-based identity through collections.** A plain string stored in an IdentityTable, a Set and
   a WeakReference, then read back after collections. Expected: the held value's `identityHash` is
   stable and the WeakReference does not clear while held. Task 1 (witness) and Task 2 (L1) pin it.
