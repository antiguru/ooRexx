# Phase 9d: divergences, reachable refusals, the queued inventory, and the Phase 9 close

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to
> implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every ooTest test with no exclusion row that the oracle passes passes here or carries a
ruled licence. Every refusal a program can reach is implemented or ruled. Every queued item has a
disposition. `json`, `yaml` and `dateparser` pass. Phase 9 closes.

**Architecture:**
* **Measure first.** Tasks 1 to 3 produce three committed tables: the 9d set and its clusters, the
  queued inventory, and the reachable refusals. Tasks 2 and 3 bring rulings to Moritz.
* **Instantiate from the tables.** Tasks 6, 7 and 8 are templates. The controller writes one
  numbered instance per cluster (6.1, 6.2, ...), per reached-refusal batch (7.n), and per accepted
  queued item or batch (8.n) into this plan before dispatching it. Each instance uses its template's
  steps.
* **Smaller fixed tasks.** Task 4 is the extension packages and Task 5 the Deviation 42 and 43
  relabel.
* **Close.** Task 9 removes Phase 9 from the labels and Task 10 closes Phase 9.

**Tech Stack:** Rust (`rexx-exec`, `rexx-core`, `rexx-parse`), the ooTest suite harness
(`rexx-exec/tests/suite.rs`, `tests/support/suite_rows.rs`), the corpus differential
(`rust/corpus/`), `bench-programs/callgrind.sh`. No new dependency unless the controller rules on it.

**Spec:** `docs/superpowers/specs/2026-10-17-phase-9d-divergences-and-close-design.md`, which holds
where it disagrees with its parent `docs/superpowers/specs/2026-10-10-phase-9-core-conformance.md`
(sections 3, 7, 8, 9, 10). Spec review: `.superpowers/sdd/2026-10-17-phase-9d-spec-review.md`.
Baseline: `docs/superpowers/plans/phase-9c-gate.md` and
`docs/superpowers/records/2026-10-15-phase-9c/close/suite/tests.tsv`.

## Global Constraints

* **Specialization is internal** (`rust/CLAUDE.md`). No refusal of the form "this crate does not
  keep X", and no side map keyed by a numeric id. `tests/representation_refusals.rs` stays green
  with `ALLOWED` unchanged.
* **Behaviour.** The corpus differential stays identical except where a task names the programs it
  changes. Each changed program is witnessed against the oracle.
  * New witnesses go in `rust/corpus/phase-9.txt`.
  * A new `corpus/lang/*.rex` needs its `crates/rexx-parse/tests/sourceline_oracle/<name>.txt`,
    generated by that test's oracle driver.
  * A witness comparing collection output compares it as a multiset (Deviation 33: hash order is
    unspecified).
* **`unsafe`**: no new site (`crates/rexx-core/tests/unsafe_sites.rs`).
* **Oracle runs**: `( ulimit -v 1048576; LD_LIBRARY_PATH=/home/moritz/dev/repos/ooRexx/build/lib
  timeout -k 5 20 /home/moritz/dev/repos/ooRexx/build/bin/rexx FILE )` from a fresh empty
  directory you `mkdir`. Compare stdout, stderr and status separately. Read
  `rust/corpus/oracle-crashes.txt` first.
* **Memory caps**: every crate interpreter run under `memcap 2G` and `timeout`. Every test binary
  and build under `memcap 8G`, `-j 4`, `CARGO_INCREMENTAL=0`, and an agent's own `CARGO_TARGET_DIR`
  under the session scratchpad.
* **Read-only**: the C++ tree, `samples/`, `build/`, `ootest/`, `oodocs/`, `testbinaries/`, `api/`.
* **Prose**: comments and docs state decisions, never a mechanism that does not exist yet, and
  never a set's size.
  * No em-dashes, no ` -- ` in new prose, no structuring semicolons.
  * A false sentence is deleted.
  * Extent claims carry the command that derived them.
  * Read every witness's stdout to confirm each path it claims actually prints.
* **Shell**: no `bash -c` or `sh -c` wrappers. `rm` only with literal absolute paths, no globs.
  * Never `git checkout`, `stash` or `reset`.
  * Reverse a mutant by an exact edit and confirm with `git diff --stat`.
  * Never `git push`.
* **Foreground checks**: every check runs in the foreground with a bound under 10 minutes.
* **Per-task check, at most 5 minutes in all:**
  * `cargo fmt --all --check` from `rust/`;
  * `cargo clippy -p <touched crates> --all-targets -- -D warnings`;
  * the test binaries covering what changed;
  * the refusal tables, `owners`, `closed_phases`, `phase_ten_reasons` and `representation_refusals`;
  * the gated release corpus (`REXX_CORPUS_GATE=1 ... --test corpus`);
  * the task's ooTest groups, run through the suite harness from `rust/`:
    `REXX_SUITE_GATE=1 REXX_SUITE_GROUPS=<g1,g2> REXX_SUITE_TABLE=<durable path>/table.tsv
    CARGO_INCREMENTAL=0 memcap 8G cargo test -j 4 --release -p rexx-exec --test suite l3_core_suite`.

  Record each command and its exit status in the report, unpiped.
* **Per-task perf check.** A task that changes the interpreter's run path (any `src/` file outside
  `builtin/` argument checking and refusal text) runs `bench-programs/callgrind.sh -B 0.5
  -p "startup interpret parse churn sayloop" pin=/home/moritz/dev/repos/ooRexx-p9-pin/rexx-run
  head=<the task's binary>` from the repo's `rust/`. The task's own delta on each program is at
  most +0.05% whole process, taken against the 9c close's figures in
  `docs/superpowers/records/2026-10-15-phase-9c/close/callgrind.txt`. The cumulative figure against
  the pin stays under +0.5%. New error and refusal construction stays `#[cold]` and out of line.
  This run is the one exception to the 5-minute bound.
* **No regression.** Every task that touches a group's code runs that group and reports any test
  whose result differs from `docs/superpowers/records/2026-10-15-phase-9c/close/suite/tests.tsv`.
* **Refusal tables**: deleting or relabelling a `Loud` site re-derives
  `rust/corpus/refusal-sites.tsv` (`REXX_REFUSAL_SITES_REFRESH=1 cargo test -p rexx-exec --test
  refusal_sites`) in the same commit.
* **Records**: outputs a record cites go in `docs/superpowers/records/2026-10-18-phase-9d/`, never
  `/tmp`. Raw callgrind files go in `/home/moritz/dev/repos/ooRexx-p9-pin/cg-9d/`.
* **Fix rounds**: three per cluster or finding. The remainder then goes to the controller, who
  takes it to Moritz with a proposed owner or Deviation.
* **Shared paths**: an item that needs a change outside its task's files is reported. The
  controller moves it, and it is not widened inside the task.

## Review Focus

1. **A fix that turns a passing test red elsewhere.** A cluster fix changes shared machinery
   (conditions, tracebacks, streams). Expect every test passing at the 9c close to still pass.
   Each Task 6 instance runs the groups its files feed, not only its own, and Task 10's join
   against the 9c close's per-test record catches the rest.
2. **The yaml copy.** The harness's crate side loads the oracle's `build/bin/yaml.cls`, which
   differs from `extensions/yaml/yaml.cls`. Expect a fix that passes against one copy to pass
   against the other. Task 4's witness uses the five-line repro from the queued item, which is
   independent of either copy.
3. **Byte names on the stream paths.** NOTREADY on directories and invalid names takes names that
   are not UTF-8. Expect the oracle's answer for a name with a `'80'x` byte. The streams cluster's
   instance adds one.
4. **Conditions under INTERPRET and through REPLY.** The traceback cluster reaches the INTERPRET,
   REPLY and propagated paths. Expect each to print the oracle's lines. The cluster's instance
   witnesses one program per path.
5. **A refusal reached only through a subclass or an enhanced object.** Task 3's enumeration is
   per class and method. Expect a pair reached only through `enhanced` or a subclass instance to be
   found. Task 3 probes each pair once through a plain instance and once through a subclass.
