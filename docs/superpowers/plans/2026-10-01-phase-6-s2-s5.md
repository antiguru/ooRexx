# Phase 6, stages S2 to S5: activities, synchronisation, the baton and the close, implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to
> implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run more than one activity per interpreter (started messages, REPLY continuations, timers),
park and wake them on guards, semaphores, messages and sleeps, move native calls and blocking
operations off a per-interpreter baton onto pooled driver threads, and close Phase 6 against the
spec's exit criteria.

**Architecture:** S1 left every resumable entry running on the driver's own frame and a park channel
from `Op::Exec` that S1 refuses. S2 first builds the both-sides group instrument, then the activity
table, the scheduler (ready queue, sleeper heap, FIFO activity numbers), a pin depth that exists in
every build, the native half of the driver's Park path, the timer thread and the deterministic switch
mode, then builds started messages, REPLY splits and parkable natives on them, all on one driver
thread. S3 adds guard locks, GUARD parking with the variable barrier (and with it the `Op::Exec`
re-run half of the Park path), the semaphore classes, unnamed `Sys*Sem`, Alarm and Ticker. S4 adds
the baton, driver exits for native calls with completions through the inbox, the driver pool with
the `Send` grant, per-activity API contexts, lent island memory and signals. S5 runs the exit
criteria, the performance gate last.

**Tech Stack:** Rust; `rexx-core`, `rexx-exec`, `rexx-api`, `rexx-bench`; `loom` (dev-dependency,
Task 15) and `libc` (direct, Task 21), both ruled (spec R4, R5).

**Spec:** `docs/superpowers/specs/2026-09-29-phase-6-concurrency-design.md` (at `50adaa724`). S0/S1:
plan `docs/superpowers/plans/2026-09-29-phase-6-s0-s1.md`, gate record
`docs/superpowers/plans/phase-6-gate.md` (S0/S1), measurements `phase-6-perf.md`,
`phase-6-pinning.md`, records `docs/superpowers/records/2026-09-29-phase-6-s0-s1/` (rulings P1 to
P22 in its `progress.md`).

## Global Constraints

* **Behaviour.** The corpus differential stays identical except where a task names the programs it
  changes (a refusal that becomes an answer); each such program is witnessed against the oracle.
  Interleaving-dependent behaviour is tested on the crate alone under the deterministic switch mode
  (spec section 9, testing rule); corpus programs witness only orderings the oracle fixes.
* **`unsafe`** stays in `rexx-api/src/ffi.rs`, `rexx-api/src/load.rs`, `rexx-core/src/bytes.rs`,
  `rexx-core/src/frame.rs`, plus `rexx-exec/src/island.rs` (D-U2, Task 18) and
  `rexx-exec/src/signal.rs` (D-U3, Task 21), each block with a `SAFETY:` note; the
  `unsafe_sites.rs` lists gain each new file in the task that adds it.
* **Dependencies:** `loom` as a dev-dependency (Task 15), `libc` direct for `signal.rs` (Task 21).
  Nothing else. No `Op::Generic`; `Op::Clause` at discriminant 0; `size_of::<Op>() == 16`.
* **Process-global state:** none, except the live-interpreter registry and the timer thread (R3,
  spec section 4).
* **No island value across a driver exit** (P6-3): from Task 17 on, a thread releasing the baton
  holds only raw handles. Every allocation remains a collection point; a continuation switch and a
  driver exit are collection points too (spec section 5).
* **The scheduler trait** gains a method only with its first caller, each with a real meaning in the
  implementation that ships (ruling P20); no `allow` or `expect` of `dead_code` on seam methods.
* **Pinning stays truthful:** a frame is pinned iff it is a Rust frame between the scheduler and its
  running driver; every new recursion site gets a `PinKind` and a `FRAME_PROBES` case. From Task 2
  the pin depth on the running `Activity` exists in every build and "pinned" means depth above zero;
  the `pinning` feature adds kind tracking only.
* **Performance: one gate, after Task 25 (Moritz, 2026-10-01).** Tasks run no callgrind or wall
  clock; each task's check is a quick "it works" run instead: the bench programs it touches run to
  completion with the right output (`rust/bench-programs/*.rex` on a release build, stdout compared
  with the base's). Task 26 is the performance gate (spec section 7's instrument: callgrind with
  glibc and ld-linux excluded, each build in its own target directory with a `Compiling` line):

  `fibfunc`'s bar is its accepted S1 figure (+1.88%, P22) plus 0.7%. Wall clock is measured and
  recorded; no layout iteration and no build-level layout control (function ordering, PGO) (P19).
  Over budget: at most three rounds, then stop for Moritz's ruling (P16).
* **Oracle runs**: `( ulimit -v 1048576; LD_LIBRARY_PATH=/home/moritz/dev/repos/ooRexx/build/lib
  /home/moritz/dev/repos/ooRexx/build/bin/rexx FILE )` from a fresh empty directory, with a

* **Read-only**: the C++ tree, `samples/`, `build/`, `ootest/`, `oodocs/`, `testbinaries/`, `api/`.
* **Prose**: comments and docs state decisions with a one-line pointer, never a mechanism that does

## Review Focus

1. **A collection while another activity is parked.** Every parked activity's roots (registers,
   slots, temps, native tails, pending results, its completion record) must be visible to the
   collector. Task 2 adds a collect-stress test that parks one activity holding values longer than
   7 bytes while another allocates.
2. **Program end with activities that never finish.** A started message waiting on itself, an
   uncancelled timer native, a blocked GUARD WHEN, an uncancelled Ticker: the oracle waits forever;
   this crate must neither exit early nor spin. Task 9 witnesses a started message waiting on itself
   and an uncancelled timer native (Task 8); Task 12 adds the blocked GUARD WHEN, Task 14 the
   uncancelled Ticker. Each is a crate-side test that the main program's output is printed and the
   process does not end while such an activity exists (killed by a timeout in the test, as the
   oracle would be).
3. **Errors in activities other than main.** An untrapped error in a started send or a REPLY
   continuation prints its traceback on that activity at once, `~hasError` answers 1 and `~result`
   re-raises; the main program continues. Tasks 3 and 6 witness both against the oracle.
4. **HALT and signals reaching parked and sleeping activities.** `SysSleep(5)` under SIGINT halts
   in about a second with Error 4.1 (measured on the oracle); a parked GUARD WHEN takes HALT when
   woken. Task 21 witnesses both.
5. **Deterministic switch mode at every opportunity.** Every criterion-1 test must give the same
   result under switch-at-every-opportunity as without it, with no inverted-wait refusal and no hang
   (criterion 9). Task 10 runs it for S2's tests; Task 25 for all.
6. **No switch under live Rust frames.** A switch swaps the inline `Activity` (P13) and happens only
   at a driver exit (P14). Every path that parks or slices reads the pin depth first (Task 2); the
   nested pinned loop (Task 5) swaps activities from inside Rust frames, so the reviewer checks that
   no `RegFrame` or arena borrow of the pinned activity is live across its swap (D-U4).
