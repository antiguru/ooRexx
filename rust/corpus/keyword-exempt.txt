# Every extracted `base/keyword` body that does not pass today, and what
# would actually make it pass. One `GROUP::METHOD<TAB>unblocked_by` per line;
# lines starting with # are comments.
#
# Measured at ooTest r13178. This is the committed set
# `keyword_assertions.rs` polices in both directions: a body here that starts
# passing is as red as a body not here that starts failing, so an improvement
# shows up in a diff rather than being quietly absorbed.
#
# The `unblocked_by` column is NOT hand-written FOR A BODY THAT FAILS LOUDLY:
# there it is the owning phase `rexx-exec`'s own message names, re-derived on
# every run, so this file cannot drift from `instruction_owner`/`expr_owner`
# and a blocker moving between phases goes red here.
#
# Two limits on that, both real:
#
#   * A derived owner says what a body hits FIRST, not what would make it
#     pass. Four bodies are known to have a second blocker behind the first
#     -- worse, they are not equivalent to the method they came from at all:
#     CALL::test_expression, CALL::test_literal and CALL::test_on_name fail
#     under the C++ oracle itself (Error 43, Routine not found) because they
#     call ::routines the standalone program does not carry, and
#     NUMERIC::test_42 exits 3 because the body falls through into its own
#     `dig: Return digits()`. All four read 4c because rexx-exec blocks on an
#     unresolved routine call first -- measured: routine "label", routine "",
#     routine "CHARIN", routine "DIGITS". Only the last two are builtins; the
#     first two are the very ::routines the standalone program does not
#     carry.
#   * The `defect:` rows below are NOT derived -- every assertion failure is
#     mapped to one constant. What has teeth for them is membership, not the
#     label: a body that starts failing its assertions and is not listed here
#     goes red as an unaccounted failure. A second defect class would need
#     the constant split by hand.
#
#   4c  770 bodies. Every phase gap in this group is 4c's and nothing else's:
#       PARSE (656 bodies), the builtin routines ARG/DIGITS/FORM/FUZZ/SIGN/
#       ..., ADDRESS, PULL. No body here is blocked by Phase 5, so 4b owes
#       this table nothing further. Which builtins are still blockers is the
#       derived half of this file and moves as they land; the run's own
#       breakdown is the current answer, never this sentence.
#
#   defect:compound-do-control-variable  6 bodies. NOT a phase gap: a real
#       divergence, confirmed by running each rewritten program under the C++
#       oracle as well, where all six pass. Every one uses a compound
#       variable as a DO control variable (`Do cv.j=1 To 5`, `Do a.i=a.i to
#       16`, `Do i.j=0 to 6 ... End i.j`). Two measured witnesses:
#         c=0; j=1; Do cv.j=1 To 5; c=c+1; End; say '['c cv.j']'
#           oracle [5 6], rexx-exec [5 CV.1] -- the control variable is never
#           assigned when it is compound.
#         a.=0; i=1; Do a.i=1 To 3; If i>7 Then Leave; i=i+1; End; say '['i']'
#           oracle [8], rexx-exec [4] -- the oracle re-resolves the compound
#           name each iteration, so which variable controls the loop changes
#           as `i` does.
#       DO is 4a's, so this is a 4a defect this 4b table surfaced. It is
#       recorded rather than fixed here: Task 11 measures, and a DO change
#       belongs with the tasks that own DO.
