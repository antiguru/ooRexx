/* ~method reads the class's own instance dictionary and nothing else
 * (RexxClass::method, classes/ClassClass.cpp:984, which retrieves from
 * instanceMethodDictionary directly).
 *
 * This is a guard against a build that flattens every scope onto one class:
 * such a build answers the rows below that raise here, and an inherited name
 * is the shape it would answer first.
 *
 * What a row covers is its own receiver and its own name; the rows below are
 * where that is written down, and a class is covered here because a row names
 * it. Each raising row's comment says which dictionary holds the name it asks
 * for, since that is what the row discriminates and is not readable off the
 * name alone. The ::ATTRIBUTE rows carry the one name shape here that is not
 * a plain symbol: a setter's resolved name carries an appended `=`.
 *
 * The pair is what pins the rule to "this class's own dictionary" rather than
 * to something coincidental: .Array~hasMethod is 1 for names this raises for,
 * so a build asking the flattened behaviour agrees with every answering row
 * and disagrees with every raising one.
 *
 * The argument is upcased before the lookup, measured -- row 2.
 *
 * The trap hides the traceback the refusals carry, so the last send is
 * untrapped and pins those bytes: the frame line the oracle emits for a
 * refusal raised inside a native method reached by a message send, and the
 * 97.1 text naming the class object as the target. rc 159.
 */

signal on syntax name trapped
n = 0

next:
n = n + 1
select
  when n = 1 then say n 'answered' .Array~method('APPEND')
  when n = 2 then say n 'answered' .Array~method('append')
  when n = 3 then say n 'answered' .Array~method('MAKESTRING')
  when n = 4 then say n 'answered' .Class~method('ID')
  when n = 5 then say n 'answered' .Object~method('HASMETHOD')
  when n = 6 then say n 'answered' .K~method('OWN')
  /* STRING is .Object's, and .Array's flattened behaviour holds it. */
  when n = 7 then say n 'answered' .Array~method('STRING')
  /* ID is .Class's instance method; .Array answers it as a class object and
     it is not in .Array's own dictionary. */
  when n = 8 then say n 'answered' .Array~method('ID')
  /* SIDE is K's own class method, which lives in the class dictionary. */
  when n = 9 then say n 'answered' .K~method('SIDE')
  when n = 10 then say n 'answered' .K~method('NOSUCHNAME')
  /* The ::ATTRIBUTE pair, whose setter's name carries a trailing `=` -- the
     only name here that is not a plain symbol. */
  when n = 11 then say n 'answered' .K~method('A')
  when n = 12 then say n 'answered' .K~method('A=')
  /* ::ATTRIBUTE ... CLASS puts its accessors in the class dictionary, the
     same place ::METHOD ... CLASS puts SIDE. */
  when n = 13 then say n 'answered' .K~method('B')
  when n = 14 then say n 'answered' .K~method('B=')
  otherwise signal done
end
signal next

trapped:
say n 'raised' rc'.'condition('E')
signal on syntax name trapped
signal next

done:
say 'hasmethod-string' .Array~hasMethod('STRING')
say 'hasmethod-id' .Array~hasMethod('ID')
say 'hasmethod-side' .K~hasMethod('SIDE')
signal off syntax
say .Array~method('STRING')

  return 'side'
