# Phase 9b1 Task 5 report: packages are collected

Status: DONE_WITH_CONCERNS. Code commit `dd5017a8e`. Records commit: see the reply.

## What changed

**The global root is gone for program packages.** `Interp::package_object` roots a freshly built
program package as a temp of the caller's frame and keeps only the REXX package under
`RootSet::add_global`. In debug builds it asserts that a program package it built is never asked for
after it was collected (`environment/identities.rs`, `package_object`). In release it rebuilds.

What keeps a program's package alive:

| holder | mechanism | where |
|---|---|---|
| an activation of its code, on the running activity | `Interp::package_roots` at each collection, through `Activity::running_programs` | `lib.rs`, `activity.rs` |
| an activation on an activity that is not running | the same, through `Activities::running_programs` | `scheduler.rs` |
| the level a failure being unwound came from | `Activity::running_programs` reads `failure_origin`; `hold_origin_package` roots it as a temp where the origin is taken off the activity | `activity.rs`, `condition.rs`, `run/condition.rs` |
| a class defined in it | `class_holds_package` (`class_owns`) in `record_package_class` and `copy_class_package` | `environment/identities.rs` |
| a `Method` or `Routine` object of its code | `record_executable` stores the package in the object (`Bound::Code`/`ScopedCode`); every program-sourced `executable_sources.insert` goes through it | `rexx-core/src/body.rs`, `identities.rs`, `install.rs`, `environment.rs` |
| a `Method`/`Routine` subclass instance | `native_as_instance` moves the package into `NativeState::Executable` | `dispatch/construct.rs`, `body.rs` |
| the interpreter's own library programs | `package_roots` | `lib.rs` |
| the package whose `::ROUTINE` first bound an external library procedure | `package_roots` over `library_codes` rows. Measured, the oracle never collects it (`rxmath`, below) | `lib.rs` |

**`rexx-core`.** `NativeObject::annotations` is an `ObjRef` with `ObjRef::NIL` for none, which frees
8 bytes for `Bound`'s `Code(ObjRef)` and `ScopedCode { scope, package }` beside `Scope(ObjRef)`.
`NativeObject` stays 104 bytes (the `const` assert). A first version used `ObjRef::NIL` as "no scope"
inside one variant and broke `context_executable_run_copy.rex` and
`context_executable_setmethod_copy.rex` (a `.nil` scope is a scope). Separate variants fixed both.

**Requires cache (Step 2).** `required_packages` stays `name -> ProgramId`, and `collect_now` drops
every entry whose package object did not survive the sweep. `load_requires` builds the package before
caching it, so an entry and its object always exist together.

**Package annotation tables** are held by the package object's own annotation slot, not by a global
root (`annotation_table`). `attach_annotations` stores the table before anything allocates.

**`representation_refusals.rs`**: no `ALLOWED` row named Task 5. The `"Task 5"` owner is removed.

### The holder

**I did not use `add_imported_package` as the dispatch asked, because the oracle forbids it.**
Measured with `say .context~package~importedPackages~items` printed before and after `x = ext5()`:
the oracle prints `0`, `0`, rc 0. If the external call imported the callee, the crate would print
`0`, `1`.

Instead, `PackageData` has a new field, `merged_from: Vec<ObjRef>`, which its trace follows.
`merge_package` (`install.rs`) appends the source package to it, once, and never the target itself.
This makes every merge hold the package it merged from: the external call, `::REQUIRES`,
`~addPackage` and `~loadPackage`. On the oracle, the merged `Routine` objects hold that package.
Here a merged `::ROUTINE` is a `MergedRoutine::Installed` that names a program, so the field takes
their place. It is not observable: `~importedPackages` still reads `imports`, and the probe prints
`0`, `0` on the fixed crate.

**Audit of the other writers of merged and public routine entries.** Each one already holds its
source package:

- `install_directives` (`install.rs:361`/`:366`) writes the package's own `routines` and
  `public_routines` for its own program.
- `~addRoutine` and `~addPublicRoutine` (`dispatch/package.rs:916`) file the `Routine` object in the
  `.ROUTINES` table, and the object holds its package through `record_executable`.
- `merge_routines` from `merge_library` and `merge_internal_package` writes only `Library` and
  `Internal` entries, which name no program.
- `merge_package` (the transitive `merged_public_routines` of the source): the target now holds the
  source, and the source holds its own sources and imports.

Classes need nothing extra: a class holds its own package.
