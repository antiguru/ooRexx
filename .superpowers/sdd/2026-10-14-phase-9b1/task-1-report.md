## Concerns

1. The new refusal message does not end "is not implemented". `corpus.rs::owner_from_stderr` and
   `gate_tables::refused_construct` group refusals by that suffix, so a run hitting this refusal is
   still loud (rc 120, `rexx-exec:` prefix) but no longer grouped under a construct name. I judged
   "names the rule, not 'this crate does not keep X'" to mean the suffix goes. If the controller
   wants the suffix kept, it is a one-line change plus the test and the TSV answer.
2. The fourth grep phrase ("is value-based") widens the brief's three. It is what lets the allow-list
   hold the objectName= row the spec requires.
3. `ALLOWED` keys rows by file and literal, not by line, so one row covers every site in a file with
   that text. Sites in one file with the same text all share one owner here.
