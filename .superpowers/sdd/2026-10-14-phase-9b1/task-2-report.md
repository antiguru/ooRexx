## What changed

* **L1** (`rexx-core/src/heap.rs`, weak pass): a WeakReference whose target is not a heap handle
  (an inline string or a small integer) is never cleared. A heap target clears as before.
  Unit test `a_weak_reference_to_a_handle_carried_value_is_not_cleared` (`rexx-core/tests/uninit.rs`).
* **L2** (`rexx-exec/src/value.rs`, `eval.rs`, `run/loops.rs`): `Interp::operand_number` is
  `to_number` for an operator's receiver. It answers `NotNumeric` for a String subclass instance
  (also through a stem's default and a variable reference), so `arith_left_operand` (binary
  arithmetic and prefix `+`/`-`) and `header_number_body` (the DO setup `+`) reach
  `operator_message_receiver` and send. Prefix `\` already sent first and is unchanged.
* **L3** (`rexx-exec/src/dispatch/reqstr.rs`): `required_string_dispatch` sends `STRING` to a class
  object as it does to an instance, so a class-side `STRING` answers `say .k`, `length(.k)` and
  `'x' || .k`.
* `representation_refusals.rs`: no `ALLOWED` row was owned by Task 2. The only "Task 2" was the
  `OWNERS` entry, which is deleted.
* Witnesses, in `rust/corpus/phase-9.txt` with their `sourceline_oracle/*.txt` (generated by the
  module's driver on a scratch copy, counts 29, 31, 15, each equal to `wc -l`):
  `lang/weak_reference_held_values.rex`, `lang/string_subclass_operators.rex`,
  `lang/class_side_string.rex`.
