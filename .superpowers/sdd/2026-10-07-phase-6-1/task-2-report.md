## Implemented

- **COUNTER, on every loop kind.** `loop_header_plan` puts a `HeaderRole::Counter` slot first when
  the loop names a counter. It has no expression: `compile` emits `Op::Const "0"` and
  `Op::LoopHeaderValue { role: Counter }`, so `DoBlock::DoBlock`'s reset and its `>=>`/`>K>` lines
  come before any header expression is evaluated. Measured: `c = 'pre'; do counter c i = 1 to c + 2`
  reads `C => "0"` in the TO expression. Each pass that is entered assigns the pass count
  (`DoBlock::setCounter`, `Interp::count_pass`) after WHILE and before the body, at the body's indent.
  A failing WHILE or advance leaves the counter where it was.
- **The flat path's per-pass cost.** COUNTER rides `flat_loop_header_general`, the out-of-line
  header WHILE loops already took. WHILE, UNTIL and "general" are bits of one `PassTest` byte. A loop
  with no counter and no WHILE runs the same step code, with no counter test (Review Focus 3). The
  nested path's `run_repeating` also handles COUNTER and WITH. No lib test or corpus program reaches
  it: a temporary `panic!` at its entry left the lib tests and the gated corpus pair with no
  `PROBE` panic (Concerns 3).
- **DO WITH.** `HeaderRole::With` evaluates the target, echoes it under `WITH` (measured), and sends
  `SUPPLIER` before FOR is evaluated, as `WithLoop::setup` does. An answer that is not a `Supplier`
  instance raises 98.994, and a target with no SUPPLIER method raises 97.1. Each pass sends
  `NEXT` (not on the first pass) and then `AVAILABLE`, which raises 34.906 when it is not logical.
  Then INDEX is bound, then ITEM, and FOR is checked only after both. All four are message sends,
  so a `Supplier` subclass sees each one. The oracle calls the base class's natives directly, and
  the output is the same. The supplier is rooted in the target's register on the flat path, and on a
  temps frame until then.
- **DO OVER a stem.** The plan no longer refuses it. `over_target_array`'s `MAKEARRAY` gives the
  tails in this crate's order (deviation 1).
- `docs/superpowers/plans/phase-4-exclusions.txt`: deviation 1's corpus rule is now "prints
  nothing that depends on the order". A false sentence at the old `:4088` is deleted.

## Concerns

1. **`emptyloop` wall clock is over ±4%** (+4.16, +4.18, +4.42 across three runs), at -0.32% in
   instructions. `perf stat` cycles: base 1.262-1.288 G, r1 1.316-1.348 G, and Task 1's `r1c`
   1.281-1.291 G. `perf annotate` puts the extra cycles in `loop_advance`, which retires
   49,999,953 fewer instructions than at base. Two further rounds were measured and not kept: WITH's state out of `LoopState` (+6.5%
   cycles) and the counter boxed in `FlatLoop` (+10%). Both read as hot-loop layout rather than
   work. Three rounds are spent, so this needs Moritz's ruling.
2. **Defects that DO COUNTER used to hide, now visible in whole groups** (each measured alone on
   both engines, with the oracle passing):
   - TRACE_TraceObject `TEST_VARIABLE`: no trace object has a VARIABLE entry.
   - `TEST_CALLER_STACK_FRAME_REPLY_START`: no CALLERSTACKFRAME THREAD entry.
   - `TEST_TRACEOBJECT_COLLECTOR`: fewer collected trace lines.
   - TRACE `TEST_TRACE_LABEL_WITH_FORWARD`: 10 trace lines against 12 across FORWARD/REPLY.
   - Method `TEST_NEW*`/`TEST_NEWFILE*`: Method NEW shapes.

   These are TraceObject, REPLY-trace and Method NEW work, not loops.
3. **`run_repeating` is unreached** by the lib tests and the corpus: every repeating loop goes flat,
   and the only `Fallback` is a labelled simple block, which returns before it. COUNTER and WITH are
   threaded through it so it stays right. Deleting it is a separate decision.
4. The queued item `2026-10-02-do-with-over-refusal` is resolved by this task. I did not close the
   queue file, which is the controller's to do.

## Fix round 1

Findings from `task-2-review.md`.

1. **I1, per-pass temporaries.** `count_pass` and `with_advance` (`run/loops.rs`) now open a frame
   per pass, as the controlled loop does, and pop it once the counter or INDEX/ITEM variable holds
   the value. `with_advance` also roots the AVAILABLE answer inside that frame. A `?` path leaves
   the frame to the outer truncation.
   - New crate test `run::tests::loops::counter_and_with_passes_do_not_accumulate_temps`. It reads
     the temporaries stack's capacity after the run as its high-water mark, through
     `Roots::temps_capacity`, a new accessor in `rexx-core/src/roots.rs`. Its assertions:
     - COUNTER's mark is the same after 100 passes and after 20000, and under 1000.
     - DO WITH over 30000 items reaches the same mark as building that collection's supplier alone.
   - RED: with only `count_pass`'s pop removed, it fails with "COUNTER: 32768 temporaries live at
     once after 20000 passes". With only `with_advance`'s pop removed, the DO WITH assertion fails.
     A probe without the pop showed temps rising 3 a pass, to 60031 over 20000 passes.
   - Peak memory, `/usr/bin/time -f %M` on release binaries, `do counter c 30000000`: before
     255,428 kB, after 18,860 kB, oracle 20,688 kB. A COUNTER DO WITH over a 1,000,000-item array:
     105,844 kB before and 105,676 kB after (the array dominates), oracle 227,556 kB.
2. **Whole-group rows.** `docs/superpowers/plans/phase-6-1-gate.md` `## Task 2` now has one line
   per newly visible failing row, each with the alone-run that shows it and its cause outside the
   loop work. Moritz's ruling on the emptyloop wall clock is recorded there too.
3. **M3.** `HeaderRole::OverFor`'s doc now names both `DO name OVER expr FOR expr` and
