## Existing helpers and reuse

`group_runner::run_process` already demonstrates a concurrent stdin writer, concurrent pipe readers, process-group ownership, and bounded child polling. Reuse its small writer pattern rather than replacing the oracle runner with the whole function, because their termination enums, memory wrappers, descendant policy, and reader bounds differ. `oracle::wait_with_deadline` already owns the deadline and independent shared reader budget, and `Oracle::run_within_env` provides a caller-selected deadline suitable for short negative controls. `oracle_deadline.rs` already supplies fresh directories and deadline classification checks, while `input_oracle.rs` supplies the separate subprocess Output path.

`group_runner::skip` and `renamed` already preserve source bytes and expose a direct pure transformation for the method-name controls. The existing `concurrency_tests::skip_changes_only_the_renamed_methods_line` exercises byte preservation on C2X and should remain intact. `suite::fixtures::scratch_run` and `crate_run_once` already provide isolated run roots and the existing Grandchild fixture, so no general process registry is needed. `rexx-bench-suite::rust_binary_candidates` is shared with benchmark main, which means a change there needs a small resolver control even though gate 472 originated in a test.

## Oracle entrypoints and boundary conditions

| Entrypoint | Input ownership and wait | Required treatment |
| --- | --- | --- |
| `run` → `run_with` → `run_within` → `run_within_env` | Optional borrowed bytes; caller/default deadline | One writer fix at the last method covers the chain. Exercise run_within_env directly and one public wrapper. |
| `run_in` → `run_in_with` | Optional borrowed bytes; default deadline; caller cwd/environment | Same writer helper, preserving cwd and child-only environment. A one-off test may pay the default 10s bound to cover the actual public entrypoint. |
| `run_with_stdin` | Caller-provided Stdio descriptor; closes unused piped writer | Leave descriptor handling unchanged. Retain input_oracle coverage for file-backed, null and closed-pipe cases. |
| `run_in_zone` | Null stdin | No input writer needed. Preserve the existing wait path. |
| `write_and_wait` | Borrowed bytes; returns std::process::Output; currently no child deadline | Start stdin concurrently with wait_with_output output draining. Fix pipe-order deadlock without silently changing its public return/termination contract. The queued oracle deadline promise is covered by bounded Oracle methods, not by claiming this existing unbounded child API acquired one. |

An unconditional writer-thread join can hang after the child is killed if a descendant retains the input read end. Use the existing runner's detached-writer pattern, or add bounded completion only if it preserves the existing wait bound; never join before starting the deadline. Copying borrowed input is necessary for a detached thread, so the regression input should be comfortably above pipe capacity, such as several MiB, while staying far below the memory caps. Preserve EPIPE as an ordinary early-exit outcome and preserve stdin EOF when the write completes.

`write_and_wait` has a separate pre-existing lack of any child deadline, documented in `input_oracle::run_rust`. Adding a new timeout API there would also change its return classification and is beyond the smallest pipe-order fix. Use a finite output-before-input program and an external foreground bound for that regression, while using genuinely nonterminating programs only through the bounded Oracle methods. If implementation discovers that a common helper cannot preserve these distinctions, report the concrete conflict before widening the slice.
