## Method introspection callers and scopes

| Path | Values supplied to method_object_for | Relevant invariant |
| --- | --- | --- |
| Object instanceMethod | introspection.rs::instance_method returns own_method_entry.executable first; otherwise receiver_selection selects behaviour or class side and lookup supplies scope/method | Object-level setMethod methods are returned as existing objects rather than reconstructed with an arbitrary scope owner. |
| Object instanceMethods | object_level_entries supplies Listed.object=Some(executable); behaviour_entries supplies graph scope/method | supplier_of bypasses method_object_for for object-level entries. It roots each constructed/existing Method before subsequent allocation. |
| Class methods | validates class_receiver, selects the class's instance behaviour, optionally filters scope | This is Selection::Behaviour, not the class-side arm at issue. Nonclass selected scopes only produce entries if already present in the behaviour. |
| Behaviour entries | graph defined_entries_at | Class-defined scopes use the defining class. Enhanced instance methods can have nil scope, with their installed Method object held separately. |
| Class-side entries | graph lookup_class_method/class_defined_entries | ClassGraph::class_define writes scope=class. cascade_build also imports the metaclass's instance behaviour, so nil scope is possible if that behaviour was enhanced. |

The tempting statement “every class-side scope is a class” is too strong. `ClassGraph::cascade_build` merges the metaclass's instance dictionary into a class-side behaviour, and `enhance_instance_methods` accepts nil-scoped methods through the supported enhanced construction. The safe claim is narrower: ordinary class-side definitions have a class scope, and the supported nil-scoped entries have existing Method objects that must be returned before reconstruction. `method_object_for` already checks scope==NIL and executable_objects first, which is exactly the decision protecting this case.

## Producer and lifetime argument

* `ClassRegistry::{add_class_method,define_class_method}` both call `ClassGraph::class_define`, whose own and flattened class dictionaries use add_method(name, class, method). Directive installation, native bootstrap wiring and define_class_method_object go through these methods.
* Ordinary class instance definitions use ClassGraph::define/define_methods and assign the class as scope. Inheritance merges existing entries, or inherit_instance_methods rewrites them to a real recipient class, and cannot invent an arbitrary nonclass scope.
* The only production call to enhance_instance_methods is class_protocol.rs::install_enhancing_methods, which passes NIL. Each method is created/scoped from an actual Method, then held with hold_method_object(dummy, false, name, executable).
* scoped_method obtains a Method identity from executable_sources and creates or reuses an actual executable. Cloned identities populate executable_objects immediately; the reused object was already registered by Method construction. hold_method_object calls class_owns(dummy, object), and rexx-core/body.rs traces every Body::Class owned object.
* Pruning removes executable_objects for dead objects/owned identities or freed source programs. A currently installed enhanced Method is strongly owned by its live dummy class, and record_executable (environment/identities.rs:554-579) stores the source package in the executable NativeState, keeping that source package alive. collect_now prunes dead-object rows before programs.free_unheld, so a live owned Method is not eligible for source-program removal. Losing that map entry while its live graph entry still names it would violate these existing lifetime invariants, rather than create a permitted nonclass owner.
* setMethod uses object-level ObjectMethod entries, including for a class receiver through its variable-pool holder. instanceMethod and object_level_entries return entry.executable directly. Native NewMethod constructs an executable, and supported SendMessage installation uses the same Rexx methods; no inspected supported native API writes an arbitrary scope into ClassGraph's dictionaries.

This is a bounded production-callsite proof, not a claim that the public Rust ClassRegistry API cannot be misused internally. enhance_instance_methods itself accepts an ObjRef scope parameter, and an artificial Rust test can pass an integer or manufacture a Selection, but that does not demonstrate a supported Rexx/native path. The two actual method_object_for call sites are instance_method and supplier_of; the latter's existing-object arm matters as much as the nil-map early return. Class-side reconstruction ultimately calls method_object(scope, true, ...), whose class_owns correctly rejects a nonclass owner if the upstream invariant is broken.

## Pool reserve outcomes and consumers

`Pool::reserve` currently returns Option<Worker>. It returns None for configured bound=0, the cfg(test) fixed-at-bound policy, and Builder::spawn failure via `.ok()?`, discarding the io::Error. Those are different policies: simulation intentionally disables the pool, a test can deliberately fix its capacity, and an actual spawn failure is a failed system service. `SysActivity.cpp:79-90` maps failed thread creation to Error_System_service_service with service text ERROR CREATING THREAD, while rexxref errnums.xml ERR48 defines subcode 001 as a failed named system service.

| Consumer | Current fallback | State/cleanup obligation when failure becomes 48.1 |
| --- | --- | --- |
| scheduler.rs::exit_for_native | Runs OffBaton call inline while holding the baton; native_call has already left Prepared and in_flight has incremented | Reserve before leave/in_flight/pin/lend transitions. Route a real failure back through the originating parked native continuation and its clause trap, dropping an unstarted call without waiting for a completion that will never exist. |
| scheduler.rs::exit_for_block → command.rs command execution | Err(block) invokes collect_on_baton; command child is already spawned | Distinguish “run inline by policy” from failure carrying the original Block. On real failure, kill/reap the owned process group and close pipes/input without entering an unbounded collect, then raise 48.1 in the command clause. |
| input.rs::fill_stdin_keeping | Reads stdin synchronously on the baton | Do not collapse a real spawn error back into the old inline path. Reset its started-read state and propagate 48.1 through the existing fallible input/stream boundary; inner bool/Option helpers currently need explicit error plumbing. |

These are all production `.pool.reserve()` consumers found by the source search, plus the direct pool test reservation. `guards.rs::reserve_for_continuation` reserves a guard lock and is unrelated to thread creation. Production POOL_BOUND=64 is an idle-retention bound, not a concurrency cap: when all workers are busy, reserve normally spawns beyond it. The test-only fix_at_bound switch exists to deliberately force inline behavior and cannot establish how an actual OS spawn error should be reported.

## Faithful deterministic failure test

Prefer the existing huge-stack seam before adding injection. scheduler/tests/pool.rs already requests a 1<<46-byte stack, and its present passing expectation relies on that thread creation failing and falling back inline. After preserving the real io::Error, first assert at the pool boundary that this request returns Err, then use the existing Shape stack override to exercise the real service-error path with bounded harmless native work. This requests no resident-memory exhaustion and does not require a full pool or thousands of threads; if the platform unexpectedly creates the thread, clean up the owned worker and report that the seam did not force failure rather than increasing resource pressure.

Only if that existing seam cannot reliably discriminate the failure on the target platform, introduce the smallest test-only seam at the existing Builder::spawn result, after enabled/idle/fixed-policy decisions and immediately before the real spawn. A per-pool or interpreter-thread-owned one-shot/countdown control should return an injected io::Error from that exact service boundary, and normal code should still use Builder::spawn unchanged. It must not force None at entry to reserve, turn bound into zero, consume an idle worker, or simulate an error after the worker was successfully created. Preserve the error in a Result<Option<Worker>, io::Error> or equally explicit private outcome, with Ok(None) retaining configured inline policy and Err identifying failed creation.

| Deterministic test | Acceptance |
| --- | --- |
| Pool enabled, no idle worker, next spawn returns EAGAIN | Err reaches the same branch as a real Builder error, spawn count does not rise, job body is not entered, and state remains usable. A second reservation succeeds after the one-shot is consumed. |
| Pool has an idle worker and a queued injection | Reservation returns that worker and does not consume the injection; only a subsequent actual spawn attempt fails. |
| Bound=0 and fixed-at-bound controls | Still select the deliberately configured inline path and do not become 48.1. Existing simulation/fixed-pool behavior remains valid. |
| Native call with another live activity and injected failure | The originating SYNTAX handler receives code 48.1 and expected service text, native body/side-effect counter remains untouched, and no fake completion, in-flight count, abandoned frame or guard hold remains. Repeating a normal call after handling the one-shot succeeds. |
| Blocking command collection with injected failure | 48.1 is trapped at the command clause, no output-collection hang occurs, and the already-created owned child/process group is reaped. Test cleanup by owned PID, not process-name scanning. |
| Stdin worker with injection | A bounded subprocess receives 48.1 rather than blocking for input; the pending-read marker cannot leave later reads permanently stuck. Keep an explicit inline-policy stdin control. |

Prefer existing scheduler/tests/pool.rs Shape/run_shaped plumbing and counters for integration tests. Add the injection setting to that test helper rather than a process-wide environment variable or an unbounded thread/virtual-memory exhaustion test. The current `a_spawn_failure_leaves_ready_activities_to_the_next_baton_holder` requests a 1<<46-byte stack and asserts the old real-failure inline behavior, so it is expected to change when this bug is fixed. Its replacement should first reuse that actual-spawn-error seam and preserve a separate inline-policy counterpart, while `a_call_on_a_pool_thread_with_no_thread_free_runs_on_its_lend` remains a valid fixed-policy control.

## Smallest responsible propagation recommendation

Keep the distinction in Pool::reserve and map actual Err to `Raised::syntax(48, 1, vec![b"ERROR CREATING THREAD".to_vec()])` through a cold named helper. Do not relabel it Error 5, a scheduler GUARD, or an arbitrary condition from the library body. Keep native reservation ahead of irreversible Prepared→Left state, because returning a scheduler error after incrementing in_flight or lending the baton leaks state. In particular, existing abandon_native_call keeps an abandoned frame until a later completion, so it cannot be reused unchanged for a call that never started.

`exit_for_native`/`exit_if_awaited` currently return unit, with exit_if_awaited called from run_until_park and run_activity_root. A simple top-level `?` is insufficient if it bypasses the originating Rexx handler or makes the wrong activity report the failure. Use the current root_step/resume_parked failure route, with explicit prepared-call cancellation, or reserve at a still-fallible native preparation boundary if that avoids broader scheduler changes without holding a reservation across an unsafe lifetime. Confirm the precise frame/guard unwind at that decision before editing, and retain a handler-continues test to prove delivery is local and state survives.

Command failure has an additional cleanup cost because start already created the child. Existing start gives that child its own process group, and collect_on_baton already demonstrates group termination on its simulated timeout, so reuse those ownership mechanics without reusing the timeout's refusal classification. Stdin reserve adds a third affected boundary outside the queue's original command/native example and must be reported as shared-path scope, not silently ignored or swallowed as inline. This evidence supports a narrow reserve-error repair, but the controller must explicitly include input error plumbing or assign it as a separate accountable follow-up.
