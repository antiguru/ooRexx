## Reaped-child race

`tests/rexxutil_process.rs::a_command_whose_child_was_reaped_elsewhere_fails_with_127` retries a race up to twenty times. A shell touches started, sleeps 0.6 and exits 5, while main polls for started and calls SysWait. `builtin/rexxutil/process.rs::wait` waits for any child, and `command.rs` maps a failed running.wait() to UNKNOWN_COMMAND=127 after output readers finish. The test's own comments admit that the command wait can win and twenty successful command waits are not evidence of a runtime defect.

First diagnostic: record per attempt the ready mark, which waiter entered first, actual child exit status/error, stdout/stderr and the command wait result, with an overall bound below ten minutes. The current twenty times sixty-second timeout loop can exceed the global bound and needs a bounded diagnostic envelope. A marker before child exit does not force SysWait to enter the kernel before the command's waiter. A longer sleep cannot establish the needed wait ownership either.

Preferred narrow repair: separate deterministic mapping coverage for an ECHILD wait failure from an integration check that child reaping may be won by either waiter. Inspect existing scheduler fault-injection helpers before adding a test-only command-wait result seam, since set_fail_native_wait exercises a different boundary and must not be assumed equivalent. Retain one process-isolated positive control showing SysWait returns the raw status for an owned child, because invoking it inside a shared test binary can reap other tests' children. If the full end-to-end losing-waiter path is required, the synchronization must explicitly hold the command wait until SysWait has reaped the child, rather than retry until the scheduler happens to cooperate.

Acceptance: 127/FAILURE mapping is deterministically red when broken and the ordinary rc=5 winner remains valid. The integration control has a fixed bounded number of attempts whose acceptance does not require one particular race winner. Do not run the uninitialized-status oracle shape from oracle-crashes entry 45. Choose whether a command-wait seam is required only after inspecting existing reusable wait abstractions.
