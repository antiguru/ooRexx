 69. A ::CONSTANT EXPRESSION'S METHOD IS ITS OWN DIRECTIVE'S (Phase 9d).
     OWNER: none.

     Ruled by Moritz 2026-10-26 ("Own clause, oracle bug"). A ::CONSTANT
     directive "defines a method that returns a constant value" (rexxref
     dire.xml:535-536); the method a parenthesised value is evaluated by is
     that directive's, so its `~source` is the directive's own clause, and
     running it again evaluates that directive's expression and leaves the
     constant's value as the directive set it. ORACLE BUG:
     `ClassDirective::addConstantMethod` (ClassDirective.cpp:536-556) appends
     every expression ::CONSTANT of a class to one `constantInitializer`
     code object, so `.context~executable` inside any of them is that one
     method. For three expressions in one class answering
     `.context~executable`, the oracle answers the third's clause as each
     one's `~source`, this crate each its own. The method of `::constant e
     (.context~executable)`, defined and sent, evaluates every expression of
     the class in order on the oracle and its own here, and on the oracle
     the run replaces the constant's value: `say (m == .c~e) (.c~e ==
     .c~method('ZZ'))` answers `0 1` there, `1 0` here. Measured by Phase 9d
     Task 8.4 and its fix rounds (t8.4/constant/probes/f8.rex;
     t8.4/r1/probes/src.rex, t8.4/r1/three-way-src.txt;
     t8.4/r2/probes/run3.rex; t8.4/r3/probes/q5d.rex,
     t8.4/r3/three-way-q5d.txt).
     Witnessed by tests::a_constant_expressions_method_answers_its_own_clause_as_source
     and tests::a_constant_expressions_method_runs_its_own_expression
     (rust/crates/rexx-exec/src/tests.rs).
