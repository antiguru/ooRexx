## Rulings made in this plan

* Ruling: the raising API takes a message constant whose type carries the catalogue's insert count
  (`Msg<N>`, generated from `interpreter/messages/rexxmsg.xml` by `rexx-inventory/build.rs`) and an
  array of exactly `N` inserts. A wrong arity does not compile, and nothing in the crate restates
  the counts. If wrong (a site needs an arity the catalogue does not give), the site's report names
  the oracle's raise site and the controller rules.
* Ruling: the old `ParseError::new(code, sub, byte)` survives Tasks 2 and 3 for the files not yet
  converted, and Task 4 deletes it. The reader's `PENDING` list of rows still raised by unconverted
  sites (keyed per row since Task 2) shrinks per task and is empty at Task 4. A test that stays red
  until the last conversion cannot gate a task.
* Ruling: the harness's `interpreter_bin` points at `rexx` in Task 5, so the task that builds
  `rexx` is witnessed by `rexx_command`. Every other caller moves in Task 6.
* Ruling: `.rxo` header. Bytes 0-19 are `#!/usr/bin/env rexx\n`. The 48-byte header that follows has
  the oracle's `fileTag` (`/**/@REXX` padded with NUL to 16 bytes), a `magicNumber` other than the
  oracle's 11111, this crate's own format version, and the source length. The source follows. `-e`
  writes the `#!` line, `/**/@REXX@\n`, then the base64 of header and source in 72-column lines, as
  the oracle does (scout C section 2). R5: no compatibility is promised between versions of this
  crate, so a header whose magic or version this build does not write is 3.903.
* Ruling: the version banner (`rexx -v`, `rexxc` without `-s`) is the oracle's
  `RexxGetVersionInformation` text (`interpreter/api/InterpreterAPI.cpp:250-278`), built from
  `version.rs`'s `VERSION` (`rexx-exec/src/version.rs:24`) so its build date is the one
  `PARSE VERSION` already answers.
* Ruling: `rexx` keeps exit status 2 for a malformed `REXX_SWITCH_MODE`, which no oracle path
  reaches (`tests/sim_processes.rs:124` asserts it).

## Global Constraints

* **Specialization is internal** (`rust/CLAUDE.md`): no refusal of the form "this crate does not
  keep X", and no side map keyed by a numeric id. A restored program is a program object like any
  other. `tests/representation_refusals.rs` stays green with `ALLOWED` unchanged.
* **Behaviour.** The corpus differential stays identical except where a task names the programs it
  changes. Each changed program is witnessed against the oracle. New witnesses go in
  `rust/corpus/phase-9.txt`. A new `corpus/lang/*.rex` needs its
  `crates/rexx-parse/tests/sourceline_oracle/<name>.txt`, generated by that test's oracle driver.
* **`unsafe`**: no new site (`crates/rexx-core/tests/unsafe_sites.rs`).
* **Oracle runs**: `( ulimit -v 1048576; LD_LIBRARY_PATH=/home/moritz/dev/repos/ooRexx/build/lib
  timeout -k 5 20 /home/moritz/dev/repos/ooRexx/build/bin/rexx FILE )`, and the same for
  `bin/rexxc`, from a fresh empty directory you `mkdir`. Compare stdout, stderr and status
  separately. Read `rust/corpus/oracle-crashes.txt` first, and never feed the oracle a truncated
  `.rxo` (it segfaults, rc 139, scout C section 2). Run every crate interpreter under `memcap 2G` and
  `timeout`, and every test binary and build under `memcap 8G`, `-j 4`, `CARGO_INCREMENTAL=0`.
* **Read-only**: the C++ tree, `samples/`, `build/`, `ootest/`, `oodocs/`, `testbinaries/`, `api/`.
* **Prose**: comments and docs state decisions, never a mechanism that does not exist yet, and never
  a set's size. No em-dashes, no ` -- ` in new prose, no structuring semicolons. A false sentence is
  deleted. Extent claims carry the command that derived them. Read every witness's stdout to confirm
  each path it claims actually prints.
* **Shell**: no `bash -c`/`sh -c` wrappers. `rm` only with literal absolute paths, no globs. Never
  `git checkout`/`stash`/`reset`. Reverse a mutant by an exact edit and confirm with
  `git diff --stat`. Never `git push`.
* **Foreground checks.** Every check runs in the foreground with a bound under 10 minutes. Never end a
  turn waiting on a background command or a monitor.
* **Per-task check, at most 5 minutes in all:**
  - `cargo fmt --all --check` from `rust/`;
  - `cargo clippy -p <touched crates> --all-targets -- -D warnings`;
  - the test binaries covering what changed;
  - the refusal tables, `owners`, `closed_phases`, `phase_ten_reasons`, `representation_refusals`;
  - the gated release corpus (`REXX_CORPUS_GATE=1 ... --test corpus`);
  - the task's ooTest groups through the suite harness, from `rust/`:
    `REXX_SUITE_GATE=1 REXX_SUITE_GROUPS=<g1,g2> REXX_SUITE_TABLE=<durable path>/table.tsv
    CARGO_INCREMENTAL=0 memcap 8G cargo test -j 4 --release -p rexx-exec --test suite l3_core_suite`.

  Record commands and exit statuses in the report, unpiped. Full gates and callgrind against the pin
  run only in Task 10, apart from Task 5's A/B (Ruled 1) and Task 7's `sayloop` run
  (Ruled 2).
* **Refusal tables**: deleting or relabelling a `Loud` site re-derives `rust/corpus/refusal-sites.tsv`
  (`REXX_REFUSAL_SITES_REFRESH=1 cargo test -p rexx-exec --test refusal_sites`), in the same commit.
* **Records**: outputs a record cites go in `docs/superpowers/records/2026-10-15-phase-9c/`, never
  `/tmp`. Raw callgrind files go in `/home/moritz/dev/repos/ooRexx-p9-pin/cg-9c/`.
* **Shared paths.** An item that turns out to need a change outside its task's files is reported,
  and the controller moves it. It is not widened inside the task.

## Review Focus

1. **An insert whose bytes look like markup.** A bad token containing `&1`, a quote, a non-UTF-8 byte
   (`'80'x` in the source) or a very long symbol. Expected: the oracle's bytes, with no insert
   re-substituted and no lossy conversion. Task 4 adds TSV rows for each and the reader checks them.
2. **A damaged or foreign `.rxo`.** This crate's image truncated inside the header, truncated inside
   the source, with a broken base64 line, and a source file whose first line happens to start with
   `/**/@REXX`. Expected: never a panic. A damaged image answers 3.903, rc 253. The source file
   answers what the oracle answers (measure it). Task 9 pins each.
3. **`rexxc` cannot write its output.** The output names a missing directory or a read-only file.
   Expected: the oracle's message and rc (measure), no partial file left as a valid image. Task 8
   pins both.
4. **Program names that are not plain ASCII.** `rexx` and `rexxc` given a name with a blank and one
   with an `'ff'x` byte, with and without the `.rex` extension. Expected: found, and reported in
   messages byte for byte (`.superpowers/sdd/queued/2026-10-13-lossy-path-sites.md` is the class).
   Task 5 pins `rexx` through its byte-named program entry, Task 8 pins `rexxc`.
5. **A restored package's relative names.** A `.rxo` in another directory whose source has
   `::REQUIRES 'helper.rex'` and calls an external routine by bare name. Expected: both resolve from
   the `.rxo`'s own directory, as on the oracle (measure). Task 9 pins it.
